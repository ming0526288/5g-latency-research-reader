# 第一步规划

**我的第一步是建立当前版本的单 UE UDP 应用 RTT 基线，给后续多 UE、TDD、SCS、分层与尾时延分析提供统一参照。**

状态：基线已建立。采用已完成独立实验 E-MEAS-01 中三个当前版本 / 256 B 精简 UDP 条件，共 6600 完整 / 6000 统计事务；本次是归类引用，没有额外重测或增加运行次数。

## 我的第一步目标

我固定源码/二进制、无线配置、调度/授权、包长、到达规律与计时边界，确认同一事务确实经过 UE、gNB 和 UPF，得到可复核的 RTT 和应用分段。机械臂只作业务背景，不加入视频或动作处理。

## 我要固定哪些条件

|条件|主线统一起点|
|---|---|
|平台|独立5GC + gNB + UE，单主机RFsim，无真实射频|
|无线|120 kHz / n261 / 100 MHz / 66 PRB / 正常CP，MCS配置上限9|
|TDD|0.625 ms：3个完整D + 混合6D4F4U + 1个完整U；具体图样是工程配置|
|调度/授权|PF / legacy / F10，SR40槽 / offset3、K2=4；既有配对私有HOL报告固定|
|业务|同一精简UDP程序，请求/响应各256 B，20 ms目标周期，不等待前一响应才发下一请求|
|统计|三个已完成同版本条件，各2200次/去200预热，各2000统计；逐轮报告，不合池|

这些取值是工程基准，不是3GPP强制的工业最佳方案。源基61654513d5、实际运行源159208eb2f，沿哈希一致10个二进制；后续修改需继续记录身份。

## 我怎样验收和使用基线

1. 核所需协议原文、代码/二进制、配置和环境身份。
2. 确认实际NAS/QFI、路由与N3/TUN事务关联，排除旁路。
3. 核计时、完整/缺失/重复和预热规则，计算同一事务RTT及可比较的上下行区间。
4. 独立复算、保存来源和失败证据；完成后进入多UE/负载对照。

目前上述三轮已核验。计时是客户端应用请求—响应，不是纯空口；跨端分段先核时钟，不加各段P99。该基线只能作为当前配置参照，不代表已实现优化收益或长期可靠性。
