## 新基线的共同启动方式

我用原核心网，在不同终端直接启动 gNB、UE；业务程序只负责发包、回复、抓包和统计。**新版 MCS 上限 9 的统一配置已在第 3 项完成接入和六次 UDP256 对照；第 1 项的原始/现在程序同条件三轮 ping 尚未完成。** 先前无连续供样的直接启动已测通，结果不冒充本轮新矩阵。

### 终端 1：核心网

```bash
cd ~/oiwireless/oiwireless-5gc-deploy
./run-5gc.sh
```

若已有其他任务占用核心或无线进程，先保留现场，不重复启动。当前测试不修改核心网。

### 终端 2：现在代码的基站

**研究版配置文件（本次仅改名）：** `gnb1.sa.band261.fr2.66PRB.5slot.low-latency.mcs9.dpdk.conf`。参数保持此前的研究配置。

```bash
cd ~/oiwireless/oi-wireless-ran-ping-slot-validation/cmake_targets/ran_build/build
sudo ./nr-softmodem -O /home/lbh/oiwireless/oi-wireless-ran-latency-analysis/research/latency-analysis/step1-native-v1/configs/gnb1.sa.band261.fr2.66PRB.5slot.low-latency.mcs9.dpdk.conf --sa --rfsim --rfsimulator.serveraddr server
```

本配置为 27.54756 GHz、n261、120 kHz、66 PRB、0.625 ms TDD，PF、HOL 关闭、UL/DL MCS 上限 9、空闲授权资格参数 0。0 是本实现更积极的资格门限，可能增加空授权；不是关闭授权或预测算法，也不能直接推广为多 UE 的唯一基线。

### 终端 3：现在代码的 UE

等基站进入运行，再开终端：

```bash
cd ~/oiwireless/oi-wireless-ran-ping-slot-validation/cmake_targets/ran_build/build
sudo ./nr-uesoftmodem --band 261 -C 27547560000 -r 66 --numerology 3 --ssb 301 --sa -O ../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/ue.oiwireless.conf --ue-txgain 0 --ue-rxgain 20 --ue-fo-compensation --rfsim --rfsimulator.serveraddr 127.0.0.1
```

两端均不加 `--continuous-tx` 或额外线程池。单机用 `127.0.0.1`，原命令的 `192.168.10.1` 只有在该地址确实属于基站且可达时才适用。等 UE 出现 `Interface oaitun_ue1 successfully configured`；TCP 已连接或只看到同步不能算用户面通过。

### 终端 4：先核网卡、路由，再发业务

```bash
ip -4 addr show dev oaitun_ue1
ip -4 route get 172.11.200.25 oif oaitun_ue1
ping -c 20 -I oaitun_ue1 172.11.200.25
```

查看实际 UE 地址；正式业务还要按该源地址核路由，不能走同机旁路。这 20 包只检查可达性，不混入正式三轮统计。启动失败时不开始业务；保存最后成功位置和失败现场，在新的输出根重试。

## 最开始源码：只换程序目录，正式对照保留共同配置

先在各自终端 Ctrl-C 停止本次 gNB/UE，再运行最开始源码，不能让两组同时争用 4043 和同一个 TUN。核心保持原部署。

```bash
cd ~/oiwireless/oi-wireless-ran/cmake_targets/ran_build/build
sudo ./nr-softmodem -O /home/lbh/oiwireless/oi-wireless-ran-latency-analysis/research/latency-analysis/step1-native-v1/configs/gnb1.sa.band261.fr2.66PRB.5slot.low-latency.mcs9.dpdk.conf --sa --rfsim --rfsimulator.serveraddr server
```

另开终端进入这个原构建目录，执行上面同参数 UE 命令。原源码/二进制和原配置文件不改；这里通过外部配置统一主要无线条件。原实现仍有已知封装/标记局限，详知识页，不能把它称为全面协议认证参照。

**原始配置文件：** `gnb1.sa.band261.fr2.66PRB.5slot.dpdk.conf`，用户最初 gNB 命令中的路径是 `../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/gnb1.sa.band261.fr2.66PRB.5slot.dpdk.conf`。它用于还原历史默认配置，和上面统一配置不是同一个条件。旧约 0.834 ms、现在默认约 2.358 ms 与低门限约 0.843 ms 的运行命令、失败轮及原因留在[独立原因页](../../研究结果与分析/源码与现在代码_时延差异原因分析.md)和 CHG/TEST，本页不混作新正式值。

## 本项正式 ping

```bash
ping -D -n -I oaitun_ue1 -c 2200 -s 56 -i 0.02 -W 2 172.11.200.25
```

两程序各三轮；每轮前 200 包预热、后 2000 包统计。`-i 0.02` 是目标间隔，真实间隔另从抓包统计。正式测试还须同时做 TUN/N3 捕获和包关联，单独运行这一条只得到 ping 自身输出。

本轮业务/捕获工具不会启动或停止 RAN，准确条件和顺序由 `step1-native-v1/plan.json` 固定；用新的输出根运行，不能覆盖旧证据。其命令写在各项下面，实际 UE 地址须从本轮读取，不能照抄历史地址。

## 停止与依据

各 gNB/UE 终端 Ctrl-C，只回收自己本次启动的程序；原核心保留，不用全局 pkill。原始运行目录不编辑源码、配置或清理文件。
