# 第六步启动命令

本步主题：**尾时延与多 UE 慢事务成因分析**。本页已按新版第一步与分终端启动方式重写；**本步专属配置/业务尚未执行，仍为待验证**。

## 先做哪件事

保持输入/授权/包长身份，准备足够样本的长时业务、慢包保留、超时/丢包和时钟关联。

## 共用启动与本步专用命令分开

核心网、单UE gNB/UE的已测分终端参考，以及接入成功后再发业务的顺序，见[第一步1：直接启动命令](第一步/1_源码与当前代码.md)。新MCS9统一基线仍在第一步准备/复测中。参考中的27.54756GHz/n261/120kHz只能用于对应单UE条件，不能直接当作本步正式测量。

|环节|本步执行要求|
|---|---|
|资料与版本|先查本地所需原文、当前计划和程序/配置身份；缺件立即停止并告知，不自行下载。|
|核心网|有空闲且本步获授权时，按原目录./run-5gc.sh确认可用；不能重启其他任务占用的核心。|
|gNB|分终端直接启动，使用本步实际审核并生成的配置；文件未准备前不填“已验证”的专用-O。|
|UE|等待基站就绪后按本步频段/身份/网络空间启动；不能仅凭TCP连接当接入。|
|业务|等TUN配置、承载、地址和路由核验后再启动本步业务；具体包长/规律/输出根按本步冻结。|
|停止|在各自终端Ctrl-C，只回收本次进程；保留他人任务和原核心，不用全局pkill。|

## 本步最容易误用的地方

不得拿60包或2000包的P99.9当可靠性保证，不能删除慢包后再统计；专属长时样本与门限必须先声明。

## 可用的只读准备检查

这些命令只查看工作区和已有进程，不会启动本步实验：

```bash
cd ~/oiwireless/oi-wireless-ran-latency-analysis
git branch --show-current
git status --short
ps -C nr-softmodem,nr-uesoftmodem -o pid,ppid,comm
```

ps无匹配进程时通常返回1，只表示当前未运行，并非无线测试失败。业务生成/抓包/统计工具可以另列，但不再用旧Python RAN编排结果代替直接启动复现。
