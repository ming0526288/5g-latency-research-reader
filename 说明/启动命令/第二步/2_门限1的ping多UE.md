## 本项命令与条件对应

|项|本项实际选择|核验要求|
|---|---|---|
|门限|1|gNB 配置必须对应，不靠文件名猜内容|
|工具|ping|与另一工具分开运行，不叠加负载|
|UE 数|1、2、3|业务前确认实际活动数，不是三 UE 都挂着只给其中一个发包|
|包长|56 B 数据区|三种 UE 数口径一致|
|参考基线|本轮补测单UE，不复用门限0的数值|旧网络隔离差异写明|

共同的核心网、gNB、逐 UE 启动和停止命令见[第二步共同启动表](../第二步启动命令.md)。选择该表的门限 1 配置。每个 UE 分终端直接启动，不能用旧 RAN 启动器代替。

## 1、2、3 UE：实际与计划逐项对应

|UE数|本轮执行|包数/预热|目标间隔|状态|
|---|---|---|---|---|
|1|本轮新链路单UE原生ping|三轮各2200/200|0.02 s|6600/6600完整；首败2200/0另记|
|2|两独立业务终端各执行下列命令|每UE200/20|每UE0.02 s|先导通过；正式三轮/固定总量待补|
|3|三独立业务终端各执行下列命令|每UE200/20|每UE0.02 s|先导通过；正式三轮/固定总量待补|

先依父页使用本项门限配置、直接启动实际需要的UE数，核TUN/NAS/路由；TUN/N3捕获先READY，再执行业务。以下是本轮双UE先导实际形式，两条分别位于两个业务终端：

```bash
sudo -n ip netns exec s2m56u0 ping -D -n -I oaitun_ue1 -c 200 -s 56 -i 0.02 -W 2 172.11.200.25
```

```bash
sudo -n ip netns exec s2m56u1 ping -D -n -I oaitun_ue1 -c 200 -s 56 -i 0.02 -W 2 172.11.200.25
```

三UE先导在保留上面两个业务终端的基础上，第三个业务终端直接执行：

```bash
sudo -n ip netns exec s2m56u2 ping -D -n -I oaitun_ue1 -c 200 -s 56 -i 0.02 -W 2 172.11.200.25
```

本轮单UE正式三轮只启动第1个UE，每轮用新的捕获/输出根，直接命令为：

```bash
sudo -n ip netns exec s2m56u0 ping -D -n -I oaitun_ue1 -c 2200 -s 56 -i 0.02 -W 2 172.11.200.25
```

实际另外用 `| tee <本轮新输出根>/ue编号/ping.log`保留原生完整输出，命令本体不由Python启动；shell管道退出0不能替代ping发收计数和包关联。四处目录必须与下表对应，失败根不覆盖。
