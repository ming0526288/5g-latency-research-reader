# 算法知识点：七种调度算法怎么选 UE

我的研究里，多个 UE 会竞争有限的无线资源。调度算法要帮助基站决定：**当前哪些 UE 先获得服务，以及如何分配可用资源。** 这里先解释排序规则；真正能否发送，还要满足可用资源和协议时序等条件。

## 七种规则先看这一张表

点击算法名称，可以进入它自己的公式、变量解释和手算例子。

|算法|中文理解|主要考虑什么|
|---|---|---|
|[RR](RR_知识点说明.md)|轮流服务|每个符合条件的 UE 按轮次获得机会|
|[MT](MT_知识点说明.md)|优先提高总传输量|同一候选资源条件下，谁当前预计能传更多数据，优先考虑谁|
|[PF](PF_知识点说明.md)|比例公平|同时考虑当前传输能力和过去获得的服务|
|[PB](PB_知识点说明.md)|业务优先级优先|优先服务重要性更高的业务|
|[EDF](EDF_知识点说明.md)|最早截止期限优先|谁的数据更接近自己的截止期限，优先服务谁|
|[M-LWDF](M-LWDF_知识点说明.md)|等待时间与传输条件结合|同时考虑等待、时延要求、当前传输能力和历史服务|
|[QUEST](QUEST_知识点说明.md)|QoS 感知调度|综合业务重要性、剩余时延预算和预计可传数据量|

## 先理解 PF，再与其他算法比较

PF 全称 **Proportional Fair，比例公平**。常见的入门表达是：

```math
\text{PF 分数}=\frac{\text{当前预计可达到的传输速率}}{\text{过去一段时间的平均传输速率}}.
```

分子表示“现在能传得怎么样”；分母表示“过去已经得到多少服务”。在其他条件相同、分母为正时，分数较高的 UE 优先被考虑。完整例子与实现边界见 [PF 的独立说明](PF_知识点说明.md)。

## 阅读这些公式前，先分清几个词

|词语|含义|
|---|---|
|UE|终端；在我的仿真里是参与通信的模拟终端|
|调度分数|用于比较候选 UE 先后顺序的数值；不是已经测到的时延|
|TBS|传输块大小；本组手算统一用 bit。它不等于应用有效数据量|
|QoS|服务质量要求；可以包含业务优先级、时延预算和可靠性要求|
|HOL|队首等待时间：当前排在队列最前面的包已经等了多久，本文用 ms|
|PDB|Packet Delay Budget，包时延预算；3GPP 的边界是 UE 与 UPF 的 N6 终结点之间，不能直接当应用通信 RTT 的期限|
|剩余预算|本组论文评分中用“预算减 HOL”近似得到的紧迫程度；不是完整链路剩余耗时的测量值|

七种算法的分数单位、取值范围可以不同，**只能在同一种规则下比较候选 UE，不能把 PF 的 4 与 QUEST 的 1800 直接比较。** 例子都假设有数据、具备调度资格、候选资源可用；数值是教学假设，不是新实验结果。

## 与我的时延研究有什么关系

这些规则可能改变多个 UE 竞争时的排队顺序。PF 便于观察吞吐公平，EDF、M-LWDF 和 QUEST 更直接利用时延相关信息。但排序公式本身不能消除所有请求、授权和 TDD 方向等待，也不能预先保证通信 RTT 或 P99 一定降低。我会在同一程序和业务条件下测量，才判断是否有收益。
