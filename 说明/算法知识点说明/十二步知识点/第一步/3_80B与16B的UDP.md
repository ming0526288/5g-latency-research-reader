# 3. 80 B 与 16 B 的 UDP 对比

## 沿用“测量部分＋剩余填充”的读法

[第 2 项知识](2_56B数据区的ping与UDP.md)已经用本机 56 B ping／UDP 解释“16 B 测量部分＋40 B 填充”。本页继续用相同读法，比较旧 80 B 与精简 16 B 两种 UDP 测量格式；两者数据区都固定为 256 B。

```text
旧格式 UDP 数据区： [ 80 B 测量字段 ][ 176 B 填充 ] = 256 B
精简版 UDP 数据区： [ 16 B 测量字段 ][ 240 B 填充 ] = 256 B
```

## 测量字段不同，数据区总长相同

|项目|80 B 格式|16 B 格式|
|---|---|---|
|UDP 数据区总长|256 B|256 B|
|项目自定义测量字段|80 B|16 B|
|零填充|176 B|240 B|
|标准 UDP 头|另计 8 B|另计 8 B|
|无选项 IPv4 头|另计 20 B|另计 20 B|
|内层 IPv4 包总长|284 B|284 B|
|序号字段|8 B|4 B|
|时间戳|包内带部分时间信息，最终接收仍须本地记录|四个时刻留在两端日志，通过 UE、轮次和序号配对|

80 B 和 16 B 都是本项目自定义的应用测量格式，不是 UDP 标准头，也不是 3GPP 的新协议头。本次没有少发送 64 B；减少的测量字段由零填充补齐。若以后固定真实业务内容、让总数据包随测量头缩小，那是另一个实验，不能混在本次结果里。

## 精简保留了什么

|功能|本次两格式是否都有|
|---|---|
|识别请求、回复及格式版本|有|
|区分 UE、轮次和包序号|有；字段范围不同|
|计算应用 RTT|有；需要同一事务发送和接收时刻|
|计算上行、回复处理和下行区间|有；需两端日志完整、同一可比较时钟域|
|直接得到 PDCP/RLC/MAC/PHY 分层时延|没有；两者都还需层内探针与关联|

80 B 原格式为两个 8 B 标记、8 B 序号、2 B 版本/类型、2 B UE、4 B 轮次，以及六个 8 B 时间槽。16 B 格式为 4 B 标记、2 B 版本/类型、2 B UE、4 B 轮次、4 B 序号。16 B 的序号范围缩至 32 bit，能覆盖本轮每次 2200 个包；不能据此宣称适用于任意长期不停机测量。

精简格式逐项相加为：4 B 格式标记＋1 B 版本＋1 B 请求／回复类型＋2 B UE 编号＋4 B 轮次＋4 B 序号＝16 B。它来自本项目精简设计；时间戳移到端点日志。16 B 与本机 ping 的计时信息同长，但内容不同，也不是论文或 3GPP 指定的布局。

旧 80 B 字段放不进 56 B 数据区，因此本项用共同的 256 B 总长来比较格式。若以后固定精简格式，另比数据区总长 56／80 B，那是包长对照；本轮没有单设总长 80 B 的 UDP 条件。

## 四个时刻怎样计时

|时刻|本轮代码中的边界|
|---|---|
|t0|UE 记录时间后，编码请求并 sendto|
|t1|服务端 recvfrom 返回后记录时间|
|t2|服务端完成请求校验、准备编码和发送回复前|
|t3|UE recvfrom 返回后记录时间，随后才校验回复|

```math
T_{UL}=t_1-t_0,\quad T_{reply}=t_2-t_1,\quad T_{DL}=t_3-t_2,\quad T_{RTT}=t_3-t_0=T_{UL}+T_{reply}+T_{DL}.
```

时间戳使用同宿主 CLOCK_MONOTONIC，按事务用整数 ns 关联、核因果顺序，再换算 ms。上行包含请求编码和系统调用等，回复区间包含校验，下行包含回复编码等；不能把这些区间当成纯空口或纯 CPU 耗时。平均值可按相同样本相加，P99 不能直接相加。

## 这次怎样保持可比

我用同一业务程序选择 `--header-bytes 16` 或 `80`，都以 50 包/秒为目标周期发送，不等待上一条回复。顺序为 16→80、80→16、16→80，各 2200 包，前 200 包预热。每个 UDP 数据区均为 256 B，用户面均经过 UE TUN、RAN、N3 和原 UPF 网络空间里的回复端。

无线条件为单 UE、n261、27.54756 GHz、120 kHz、66 PRB，0.625 ms TDD（3D＋6D4F4U 混合槽＋1U），PF、HOL 关闭、资格 0、MCS 上限 9。上限不是逐 TB 固定值；采到的运行日志报告 MCS 9。实际 NAS 与 N3 核对 5QI 9/QFI 9，捕获内核丢弃为 0，双向事务逐一关联。核心/gNB/UE分终端直接启动，不加连续供样或额外线程池。

本轮有三组配对和反序，但没有把每次业务的无线帧内起始相位锁成一样，也未隔离所有主机波动。因此只报告这批结果，不把小差值直接认定为测量格式的因果效应，不以 6000 个统计包证明 P99.9 可靠性。
