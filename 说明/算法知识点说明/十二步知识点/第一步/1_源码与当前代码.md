### 为什么指针错误需要那个星号

`n_rb_sched` 指向调用方的“剩余 RB 数”。若调度前预算为 $B$，本次重传占用 $r$ 个 RB，调用方应该得到：

```math
B_{\mathrm{after}}=B_{\mathrm{before}}-r.
```

`n_rb_sched -= r` 改的是局部地址；`*n_rb_sched -= r` 才改该地址指向的数值。例如预算 66、已占 5，本变量应该变为 61。这是 C 调用语义和本实现的预算不变量，不是 3GPP 规定只能有 66 个 RB。频域资源位图仍有其他检查，不能从这个错误直接推出“每轮必然重复分配了资源”。

### 为什么 MAC 子头也会影响资源预算

限定普通六位 LCID、非 UL CCCH 等本次使用分支，设 MAC SDU 长度为 $L$ B，可用剩余空间为 $A$ B：

```math
h(L)=\begin{cases}2,&1\le L<256,\\3,&256\le L\le65535,\end{cases}
\qquad L+h(L)\le A.
```

子头也占 TB 空间，所以不能始终扣 3 B，也不能只修改 F 位而不修正缓冲指针和可请求字节数。例如 $A=258$ B 时最大正载荷为 255 B，$A=259$ B 时可以装 256 B。这里的 TB/MAC 开销不能与 N3 外层 IP/UDP/GTP-U 头混在一起计算。

## 连上 RFsim 和完成 UE 接入不是同一件事

RFsim 的 TCP 连接用于传输模拟无线采样。连上它以后，UE 还要得到足够的采样、搜索同步信号，再推进后续接入；不能把“TCP 已连接”当作“已经能发业务包”。

|日志或代码现象|这份实现的实际含义|不能据此得出的结论|
|---|---|---|
|先显示连接建立，又显示 `connect failed, errno(0)`|`startClient` 把 failed 日志写在成功分支外，成功后也会打印，并额外 sleep 1 s|不能把这行当成连接失败，或认为 IP 必然写错|
|客户端刚连入时出现时间倒退 1 个采样的警告|`flushInput` 用“上次写入终点减 1”发送长度为 1 的时间对齐包；警告条件恰好会命中|不能仅凭这一条认定时钟紊乱、CPU 不够或 UE 无法接入|
|UE 尚未输出同步搜索或接入完成记录|`UE_thread` 先读两个无线帧，再提交同步搜索；日志尚未证明这一过程完成|不能直接跳到 SR、BSR、QoS 或业务调度问题|

源码位置是最开始源码 `radio/rfsimulator/simulator.c` 的 `startClient`、`flushInput`、`rfsimulator_write_internal`、`rfsimulator_read`，以及 `executables/nr-ue.c` 的 `readFrame`、`UE_thread`。两个无线帧是代码的预读要求，不是本次测到了 20 ms 接入时间。

RFsim 读取会等待对端采样时间戳足够；UE 的初始读取在读完一个槽后才回送 dummy 采样。同时 gNB 的 TDD 混合槽发送长度与连续供样选项有关。这形成了需要核查的读写等待条件，**目前只是运行故障候选机制**。旧现场没有保留线程堆栈、双方采样计数和 RFsim 采样流抓包，不能据源码就宣称这次一定发生了死锁，也不能宣称 `--continuous-tx` 已经解决问题。

协议背景是本地已读 [TS 38.213 V19.5.0 §4.1](#/protocol/38.213?clause=4.1&version=19.5.0)：小区搜索用于获得时间/频率同步并检测物理小区标识。TCP 实现、日志位置、预读数量、25 s 等待和连续供样选项属于这份软件的工程实现，3GPP 不指定这些 C 写法；本轮不新增时延模型或算法收益结论。
