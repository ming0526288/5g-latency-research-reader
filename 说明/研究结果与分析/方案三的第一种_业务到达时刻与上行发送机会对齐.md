# 方案三的第一种（业务到达时刻与上行发送机会对齐）

我先让**周期业务生成的包赶上已有的上行槽**。在 200 MHz、单 UE、门限 0 的基线里，UE 在槽 0 收授权，在槽 4 发上行数据。已有 57 个统计包在入队前就收到随后用上的授权。只要数据在槽 4 的 MAC 取包前准备好，就有机会搭上这次发送。[逐包定位结果](100到200MHz单UE时延方案三_上下行发送机会.md)

## 提前安排采样的对照结果

**从样本生成到收到回复，平均时延从 1.437 ms 降到 1.324 ms，P99 从 2.090 ms 降到 1.757 ms。** 这是 200 MHz、120 kHz、132 PRB、单 UE、门限 0 的 RFsim 对照。我用同一 56 B UDP 工具模拟周期采样，两组都在样本生成后立即发包。总速率目标 50 包／秒，两种方式在同一轮正反顺序交错。各发 200 包、各收到 200 个回复，分别去掉前 20 个预热包。

| 指标 | 原定时采样 | 提前采样 |
| --- | ---: | ---: |
| 样本生成到收到回复，平均 | 1.437 ms | **1.324 ms** |
| 样本生成到收到回复，P99 | 2.090 ms | **1.757 ms** |
| 上行 UE TUN → N3，平均 | 0.771 ms | **0.650 ms** |
| 下行 N3 → UE TUN，平均 | 0.523 ms | 0.528 ms |
| 赶上采样后的首个上行组包位置 | 153／180 | **178／180** |
| 共同周期起点到收到回复，平均 | 2.291 ms | **1.617 ms** |

提前组平均比原定时刻早生成 **0.557 ms**，180 个统计包都提前生成，其中 178 个发在预定上行槽。仅从实际生成开始计时，平均节省 **0.112 ms（约 7.8%）**，P99 节省 **0.333 ms（约 15.9%）**。主要变化在上行。按共同周期起点计算的 **0.674 ms** 改善包含提前生成带来的收益，因此两种时延口径分别报告。

## 怎样安排采样

我为每个周期设定一个共同最早采样时刻，即原定采样前 0.850 ms。提前组用最近 7 次连续授权的主机时间估计下一次授权，把生成时刻设在预计授权之前 50 μs，并限定在允许的采样窗口内。正常组在原定时刻生成。两组都记录实际生成时刻，并沿用同一授权和无线图样。业务发送后再用同包的 RLC、DCI、PHY 和基站 CRC 验证是否赶上目标槽，400 个包的关联均通过。

结果适用于**采样时间可调整的周期业务**。这轮用程序生成请求模拟传感器采样，统计样本每组 180 个，尚需独立重复检验尾时延。汇总见 `数据/方案三第一种_200MHz单UE_提前采样_20261120.json`。

## 首轮结果：到点后再等授权

**包已经要发时，再等下一次授权，反而增加了完整时延。** 固定原 200 MHz、120 kHz、单 UE、门限 0 和 5 槽 TDD，使用同一 56 B UDP 请求—回复工具，目标总速率 50 包／秒。在同一轮交错安排「到点发」和「等到下一次 UE 授权再发」。两组各发送 200 包、各收到 200 个回复，前 20 包预热，分别统计后 180 包。这里新测的是 UDP，原生 ping 仍作为此前的机制诊断。

| 指标 | 到点发 | 等下一次授权再发 |
| --- | ---: | ---: |
| 从业务触发到发出，平均 | 0.093 ms | 0.280 ms |
| 发出到收到回复，平均 | 1.369 ms | 1.391 ms |
| **业务触发到收到回复，平均** | **1.461 ms** | **1.671 ms** |
| **业务触发到收到回复，P99** | **1.971 ms** | **2.499 ms** |
| 上行 UE TUN → N3，平均 | 0.724 ms | 0.743 ms |
| 下行 N3 → UE TUN，平均 | 0.507 ms | 0.515 ms |
| 赶上触发后首个观测到的上行组包位置 | 128／180 | 49／180 |

等待授权组有 **78／180** 个包用上了业务工具选中的目标槽。其余包最终在别的目标槽发出。两组都按原触发时刻起算，等待组的完整平均时延增加约 **0.210 ms**，P99 增加约 **0.527 ms**。用于判断「第一机会」的边界是 UE 目标槽实际组包的探针时刻。两端只读探针在业务结束后写满，完整记录覆盖全程及两侧余量，400 个包均完成 TUN、N3、授权和目标槽关联。

此前 180 个 ping 的离线分组也留作参考。已提前拿到后来用上授权的 57 个包，上行均值为 0.563 ms，其余 123 包为 0.766 ms。这说明到达与授权的相对时机值得研究。两组来自既有自然到达记录，差值只描述这批包。
