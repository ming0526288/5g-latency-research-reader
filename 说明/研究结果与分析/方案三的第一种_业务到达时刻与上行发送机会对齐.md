# 方案三的第一种（业务到达时刻与上行发送机会对齐）

[本项启动命令](../启动命令/独立实验启动命令.md#方案三的第一种业务到达时刻与上行发送机会对齐)

我想验证的是，调整周期业务的发包时刻，能否让包更容易赶上已有的上行发送机会。

## 从 56 B ping 看到什么

在 200 MHz、120 kHz、132 PRB、单 UE、门限 0 的现有图样里，基站在周期槽 0 发授权，UE 在槽 4 发上行数据。对同一轮 180 个统计包逐包核对后，有 57 个 ping 在进入队列前，UE 已经收到这个包后来用到的授权。[逐包定位结果](100到200MHz单UE时延方案三_上下行发送机会.md)

| 自然发包观测分组 | 样本数 | 上行 UE TUN → N3 平均时延 |
| --- | ---: | ---: |
| 入队前已收到随后用到的授权 | 57 | 0.563 ms |
| 入队时还未收到随后用到的授权 | 123 | 0.766 ms |

这是按既有 56 B ping 的到达时机分组得到的差异。验证调整发包时刻的效果，需要主动改变发包时机，再与自然发包作对照。

## 56 B ping 的相位对照待测

固定无线配置和目标发包间隔，比较自然发包与对齐到既有上行机会的发包方式。逐包核对实际发出时间、所用授权和上行槽，再比较往返时延、上行分段和丢包。相位对照的 ping 实测结果待补。

时隙长度和 TDD 方向依据 TS 38.211 V19.5.0 §4.3.2 表 4.3.2-1、TS 38.213 V19.5.0 §11.1，目标槽分配依据 TS 38.214 V19.5.0 §6.1.2.1。业务相位分析参考 P30 v3 §III、图 2、§IV.A（本地 PDF 第 3–4 页）。采样时刻、余量和对照口径由本项目选取。[LatencyScope v3](https://arxiv.org/abs/2511.21277v3)
