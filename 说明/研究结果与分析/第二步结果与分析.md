## 200 MHz、门限 0 的 ping 独立短测

使用 RFsim、n261、120 kHz、132 PRB、0.625 ms TDD、MCS 上限 9、PF 和空闲探测后置。核心网和三个 UE 身份沿用第二步。单、双、三 UE 都从同一个已启动的基站逐台接入，依次测三个独立组。每台发 200 个 56 B 请求，目标每秒 50 次，前 20 个预热。

|终端数|每台发出／收到|逐台平均 RTT／ms|逐台 P99／ms|
|---|---:|---|---|
|1 UE|200/200|1.354|1.951|
|2 UE|各 200/200|2.945 / 3.064|4.204 / 4.327|
|3 UE|各 200/200|4.029 / 4.372 / 4.616|5.581 / 6.029 / 7.199|

每台统计 180 个样本。双 UE、三 UE 的共同统计时段分别为 2.895 s、2.834 s。TUN 和 N3 双向按包关联，QFI 9，零抓包内核丢弃。

**和 100 MHz 三 UE 后置短测相比，第三台均值从 7.187 ms 降到 4.616 ms，前两台从 2.241 / 2.292 ms 升到 4.029 / 4.372 ms。** 三台中最快与最慢的均值差由 4.946 ms 缩到 0.587 ms。第三台的上行抓包段从 6.277 ms 降到 3.050 ms。放宽软件名额可能参与这项变化。为配置 200 MHz，本次同时调整了频点并提高了采样率，且没有开启逐次授权观测，所以结果只比较两套配置的短测表现。原 100 MHz 的单 UE 值来自另外三轮，双 UE 原短测也使用不同的探测顺序。

第一次 200 MHz 启动的派生配置漏了已有 RFsim 同步项，UE 连上 TCP 后未进入同步，业务未开始。补回同一同步项后，三组均完成。测量结束后一个 UE 的退出码为 1，随后核对无线和抓包进程已全部回收。详细终止状态见 TEST633。

### 单 UE 多出来的时延在哪里

用 100 MHz 的三轮原记录和 200 MHz 的单 UE 短测，按同一组 TUN／N3 抓包点做离线复算。两边均为 56 B、门限 0、120 kHz 和每台目标每秒 50 次。100 MHz 使用 6,000 个统计样本，200 MHz 使用 180 个。

|平均时延|100 MHz|200 MHz|增加量|
|---|---:|---:|---:|
|上行请求，TUN 到 N3|0.432 ms|0.731 ms|0.299 ms|
|核心网侧往返，N3 请求到 N3 回复|0.040 ms|0.061 ms|0.021 ms|
|下行回复，N3 到 TUN|0.332 ms|0.545 ms|0.214 ms|
|ping 程序报告的 RTT|0.820 ms|1.354 ms|0.534 ms|

上行与下行合计解释了约 **96%** 的增加。前三行来自同一事务的捕获，求和是 TUN 侧的往返。最后一行的计时来自 ping，应用计时边界略有差别。

单 UE 时没有其他终端占用探测名额。两档的 120 kHz 和 0.625 ms TDD 保持一致，单个时隙仍是 0.125 ms。200 MHz 增加了每个时隙能装的数据，当前 RFsim 还把采样率从 122.88 提高到 245.76 MS/s，因此每个时隙需要处理更多仿真采样。对 56 B 小包，等调度机会和处理这些采样都可能影响 RTT。抓包可以定位到终端与基站之间的上、下行路径，尚无逐包调度和主机处理计时来量出各自的贡献。

两组还有隔离网络、基站构建、探测顺序和频点差异，实发平均间隔约为 24.784 ms 和 20.417 ms。现有结果能说明增量出现在哪里。要判断采样处理或授权等待分别贡献多少，需要同一构建、探测策略、网络与发包口径的对照，并记录调度与主机处理边界。

分段复算来源为 TEST611、TEST633 与 TEST634。N3 路径见本地 TS 38.300 V19.4.0 §4.3.1.1，时隙见 TS 38.211 V19.5.0 §4.3.2。采样率来自项目 `nr_common.c` 的 66／132 PRB 分支。逐包计时参考 P01 §III–IV、本地 PDF 第 2–4 页。
