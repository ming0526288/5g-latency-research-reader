# 100 到 200 MHz 单 UE 降低时延方案一（针对本机 RFsim 变慢）

[本项启动命令](../启动命令/独立实验启动命令.md#方案一本机-rfsim-四分之三采样)

我验证了 OAI 的四分之三采样选项 `-E`。**在本机 200 MHz、120 kHz、132 PRB 配置下，启用后基站在处理随机接入时退出，UE 未接入，因此没有测到这一档的 RTT。** 切回默认采样后，单 UE 恢复接入，200 个 ping 全部收到回复。

## 默认 → 四分之三采样 → 切回默认

三轮使用同一套基站和 UE 程序、同一核心网、n261、27.61236 GHz、200 MHz、132 PRB、120 kHz、0.625 ms TDD、MCS 上限 9、门限 0 和空闲探测后置。唯一切换的无线启动选项是 gNB 和 UE 是否同时加 `-E`。接入后，发送 200 个 56 B ping，前 20 个作预热，后 180 个用于统计。

|轮次|RF 接口报告采样率|PHY 帧参数等效采样率|接入及业务|平均 RTT|P99|
|---|---:|---:|---|---:|---:|
|默认采样|245.76 MS/s|245.76 MS/s|成功，200/200|1.278 ms|1.522 ms|
|两端加 `-E`|184.32 MS/s|368.64 MS/s|基站在随机接入处理退出，业务未开始|未测|未测|
|切回默认采样|245.76 MS/s|245.76 MS/s|成功，200/200|1.327 ms|1.888 ms|

两轮默认采样均验证 TUN 和 N3 路由、逐包匹配和抓包完整性。两轮实发平均间隔为 20.385、20.414 ms。表中 P99 描述本次短测样本。

## 为什么这套配置用不了 `-E`

1. **资源栅格需要 1,584 个子载波。** 132 个 PRB，每个 PRB 有 12 个子载波，所以资源栅格宽度是 1,584 × 120 kHz，即 190.08 MHz。这里的 190.08 MHz 表示资源栅格，200 MHz 是信道标称带宽。
2. **按接口的 184.32 MS/s 只对应 1,536 个 FFT 点。** 保持 120 kHz 间隔时，184.32 MS/s ÷ 120 kHz = 1,536，小于 1,584。当前 OAI 初始化的四分之三采样分支按 384、768、1,536、3,072 递增，于是选了 **3,072 点**。每子帧实际要处理 368,640 个基带样本，相当于 **368.64 MS/s**。
3. **射频接口与基带选出了两套规格。** 基站日志仍报告接口采样率 184.32 MS/s，但 PRACH 随机接入接收程序用的是物理层每子帧的采样数。它遇到 368,640 时触发断言，日志为 `sample rate 368.640000 MHz not supported for numerology 3`。基站退出码为 1，UE 随后连接 4043 被拒绝，未取得 TUN 的 IPv4 地址。

**本轮结论**是当前程序的 200 MHz、132 PRB 配置保留默认采样。OAI 文档中的四分之三采样属于实现选项，适用性要按资源栅格和执行路径核验。这里验证的是本机 RFsim，真实射频性能需要在对应链路上测量。

标准依据为 TS 38.104 V20.1.0 §5.3.2 表 5.3.2-2、TS 38.211 V19.5.0 §4.4.4.1 和 §4.3.2 表 4.3.2-1。FFT 选择、采样率和断言来自项目的 `nr_parms.c`、`nr_common.c`、`nr_prach.c`。实际命令和证据入口见 CHG-482、TEST-637。[OAI 的四分之三采样说明](https://github.com/OPENAIRINTERFACE/openairinterface5g/blob/develop/radio/rfsimulator/README.md#how-to-improve-performance)

## 换成真实射频后，能用 `-E` 降时延吗

这次实验的价值是排除了当前 200 MHz 配置下的 `-E` 方案。它在业务开始前就退出了，因此没有降时延数据。真实射频由硬件采样时钟推进。支持四分之三采样的硬件和驱动可以减少要搬运的数据量，能否缩短 RTT 还要看基带处理是否原本卡在业务路径上。120 kHz 的时隙仍为 0.125 ms。OAI 把 `-E` 作为有设备和配置条件的实现选项。[OAI 真射频 UE 文档](https://github.com/openairinterface/openairinterface5g/blob/develop/doc/NR_SA_Tutorial_OAI_nrUE_GPU_offload.md)

## 原来的真实射频配置，改成 200 MHz 能适配吗

我核对了原构建和本次研究构建。两者的 `liboai_device.so` 都指向同一份 `liboai_dpdkrfdevif.so`。当前真实射频的 DPDK 驱动在 `device_init` 检查采样率，最高列出的档位为 **122.88 MS/s**，该档发射和接收都设为 **100 MHz**。其他采样率进入 `unknown sampling rate` 分支并退出。下表根据本地 `nr_common.c` 给出的配置值和原驱动代码核对。

|n261、120 kHz 配置|gNB 射频接口所需采样率|当前真实射频 DPDK 驱动|
|---|---:|---|
|100 MHz、66 PRB，默认采样|122.88 MS/s|有对应档位，和原有配置一致|
|100 MHz、66 PRB，加 `-E`|92.16 MS/s|没有该档位|
|200 MHz、132 PRB，默认采样|245.76 MS/s|没有该档位|
|200 MHz、132 PRB，加 `-E`|184.32 MS/s|没有该档位，基带本身也有前文的 FFT 与 PRACH 限制|

**因此当前驱动不能直接从 100 MHz 升到 200 MHz，也不能靠 `-E` 绕过去。** 3GPP 给 n261、120 kHz 列出了 100 MHz 和 200 MHz 两个档位。要让实验室的真实射频链路跑 200 MHz，需要支持该带宽和采样率的驱动、射频设备及固件，承载样本的接口和现有 3.1 GHz 中频链路也要支持对应带宽，终端需要支持同一无线配置。单凭原来的 100 MHz 可以工作，还无法判断硬件本体的 200 MHz 能力。本次核对只读了源码和已编译的库，真实 200 MHz 接入与 RTT 尚未测量。

依据为 TS 38.104 V20.1.0 §5.3.2 表 5.3.2-2、§5.3.5 表 5.3.5-2，以及 TS 38.101-2 V20.1.0 §5.3.2 表 5.3.2-1、§5.3.5 表 5.3.5-1。驱动初始化入口和构建库核验见 CHG-483、TEST-638。[3GPP 基站射频规范](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3202) · [3GPP FR2 终端射频规范](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3284)

### 当前 DPDK 的档位能调吗

**可以通过无线配置选择现有档位。能新增多高的档位，要看驱动、固件和射频硬件。** DPDK 提供高速收发数据的框架。这里的采样档位来自项目的 `liboai_dpdkrfdevif.so` 和本机安装的底层 `libdpdkrf.so`。[DPDK 官方说明](https://doc.dpdk.org/guides/prog_guide/overview.html)

|OAI 射频适配层接受的采样率|适配层填入的收／发带宽|传给底层库的档位系数|
|---:|---:|---|
|122.88 MS/s|100 MHz|1|
|61.44 MS/s|40 MHz|2|
|30.72 MS/s|20 MHz|4|
|15.36 MS/s|10 MHz|8|
|7.68 MS/s|5 MHz|此分支未单独设置|
|1.92 MS/s|1.25 MHz|此分支未单独设置|

本机底层库的 `setDataRate` 只识别 1、2、4、8，按 `1,228,800 ÷ 系数` 设置 10 ms 帧的样本数，对应上表前四种采样率。因此源码里有六个适配入口，只核实到四种明确的底层档位控制。最下面两项仍需设备实测确认。

调整时，OAI 根据频段、子载波间隔、资源块配置和采样选项算出所需采样率，射频适配层再从表里匹配。例如 n261、120 kHz 的 **50 MHz** 在标准中有对应配置，OAI 默认采样是 **61.44 MS/s**，但该驱动分支写入的是 **40 MHz**。所以采样率能过驱动初始化，仍需核对射频带宽和终端配置，才能判断能否接入和正常跑业务。

对 **200 MHz**，默认配置需要 **245.76 MS/s**，既超出当前适配层，也无法用现有底层的分档表达。即使获得支持 200 MHz 的硬件或固件，也需要匹配的驱动及采样传输配置。现有信息只能确定软件边界，硬件自身的上限仍需查设备规格和固件版本。这里的采样分档是实现选择，3GPP 对应的是信道带宽和资源块配置。核查见 CHG-484、TEST-639。
