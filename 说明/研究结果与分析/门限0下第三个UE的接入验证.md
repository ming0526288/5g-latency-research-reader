# 门限 0 下第三个 UE 为什么接不进来

在这套 120 kHz 仿真配置下，原调度顺序会让前两个终端（UE）的空闲探测先用掉同一轮的两个上行调度名额。即使第三个 UE 已向基站请求资源，也可能连续被跳过。我保留门限 0，将纯空闲探测放到已有请求和待发数据之后，三个 UE 都完成了接入，短 ping 各收到 20/20 个回复。切回原顺序，接入异常再次出现。

## 为什么两台可以，三台会卡住

空闲探测是基站在暂未收到数据需求时，主动给 UE 一个小的上行发送机会。门限 0 在本配置中让 UE 达到 5 个时隙的空闲资格时，就可以参与探测分配。5 个时隙对应 0.625 ms，实际是否授权仍由调度决定。

当前实现用 66 ÷ (4 × 6) 向下取整，得到普通上行调度每轮约 2 个 UE 名额。其中 66 是上行载波的 PRB 数，4 是代码采用的平均聚合等级，6 是每个 CCE 的 REG 数。两个 UE 时，两份名额可以分别服务两台终端。加入第三台后，如果遍历在前的两台每轮都先获空闲探测授权，后面的第三台就会被跳过。这里的两个名额属于当前实现的每轮估算，小区能同时接入的终端数要看多个轮次能否轮流服务。

我在原构建的门限 0 对照里，看到第三个 UE 的 SR 已在基站标记为待服务的 33,244 个调度轮次。其中 33,229 轮（99.95%），前两个 UE 当轮都在没有 SR、没有已知积压时获得探测授权，第三个 UE 则因名额耗尽被跳过。这个比例按基站调度轮次计算，一次 SR 可以跨多个轮次保持待服务。UE 侧实际两次达到 64 次的 SR 重试上限，随后反复发起随机接入。

## 怎样让三个 UE 接入

|实验条件|接入结果|56 B ping 连通检查|
|---|---|---|
|原构建、门限 0、原调度顺序|前两个 UE 有业务地址，第三个反复随机接入|三 UE 业务未开始|
|原构建、门限 1、原调度顺序|三个 UE 都完成接入|每个 UE 收到 20/20 个回复|
|同一试验构建、门限 0、空闲探测后置|三个 UE 都完成接入|每个 UE 收到 20/20 个回复|
|同一试验构建、门限 0、切回原顺序|第三个 UE 再次反复随机接入，随后基站在 Msg4 重传分配时退出|三 UE 业务未开始|

只改配置时，可用门限 1 建立三 UE 链路。要保留门限 0，本次跑通的做法是基站先处理已有待发数据或收到的 SR，最后再用剩余名额安排纯空闲探测。反向对照使用完全相同的试验二进制，只切回调度模式。它再次记录到第三个 UE 的 28,992 个待服务轮次中，有 28,990 轮在前两次空闲探测用完名额后被跳过，UE 四次达到 SR 重试上限。

原构建的门限 0 测到重复接入后主动停止。反向对照则记录到 Msg4 重传时，基站发现可分配的传输块装不下待发数据，触发断言，这解释了那轮基站退出的直接原因。原调度导致的 SR 长期未获服务，和 Msg4 重传处的退出，是排查中看到的两个阶段。

## 结果适用范围

本次为同一宿主机的 RFsim 接入验证，沿用 66 PRB、0.625 ms TDD、原核心网和相同的三个软件 UE。修正组保留的调度记录覆盖第三个 UE，基站缓冲区在后段达到容量上限，丢弃了 201,657 条观测记录。三个接口的地址、路由和 60 个 ping 回复均另行核实。短测只支持接入和双向连通，正式三轮时延、尾时延和长时间稳定性还待测量。此前第二步正式表仍对应原调度顺序。

依据：TS 38.321 V19.4.0 §5.1.5、§5.4.1、§5.4.4 和 §5.4.5 用于区分随机接入竞争解决、授权、SR 和 BSR。TS 38.211 V19.5.0 §4.3.2、§7.3.2.2 用于解释时隙及 CCE/REG。名额计算、门限 0 的空闲资格和纯空闲探测处理顺序来自本项目 `gNB_scheduler_ulsch.c`。实验命令、计数及证据边界见 CHG467／TEST622。
