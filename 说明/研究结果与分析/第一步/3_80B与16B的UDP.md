# 3. 80 B 与 16 B 的 UDP 对比

[规划](../../文献导读/第一步/3_80B与16B的UDP.md) · [知识点](../../算法知识点说明/十二步知识点/第一步/3_80B与16B的UDP.md) · [启动命令](../../启动命令/第一步/3_80B与16B的UDP.md) · [返回第一步结果与分析](../第一步结果与分析.md)

## 本次实测结果

2026-11-16，使用现在代码、单 UE、120 kHz、原核心网和低时延授权配置。两种格式的 UDP 数据区都固定为 **256 B**，同一业务程序、目标周期 20 ms，各测三轮。每轮 2200 包，前 200 包预热、后 2000 包统计；共 13200 个完整事务、12000 个统计事务，全部收齐。

|测量格式|平均 RTT / ms|每轮 P99 范围 / ms|最大 RTT / ms|
|---|---:|---:|---:|
|80 B|**1.319**|1.529–1.855|17.274|
|16 B|**1.339**|1.794–1.854|17.159|

平均值按两种格式各 6000 个统计事务计算；P99 列是三个单轮 P99 的最小—最大值，不是置信区间。慢包全部保留。

## 上下行分别是多少

|测量格式|平均上行 / ms|平均回复处理 / ms|平均下行 / ms|
|---|---:|---:|---:|
|80 B|0.934|0.0166|0.369|
|16 B|0.950|0.0135|0.375|

这里按同一事务的四个应用时刻计算，上行、回复处理和下行的平均值之和等于平均 RTT；表中有四舍五入。不是纯空口耗时，也不是机械臂动作闭环。

## 结论

**本次没有测到 16 B 头降低 RTT。** 两者平均值接近，16 B 组本次约高 0.020 ms，三轮 P99 也没有稳定下降。

原因首先要看清比较对象：80 B＋176 B 填充与 16 B＋240 B 填充都等于 256 B，内层 IPv4 包都为 284 B，总包长没有变小。精简测量字段不能直接当作无线时延优化收益。三组对照未锁定完全相同的无线帧内到达相位，也未单独隔离主机波动，因此不能进一步断言这 0.020 ms 就是格式本身造成的退化。

本轮采用 PF、HOL 关闭、资格参数 0、UL/DL MCS 上限 9，TDD 为 0.625 ms 的 3D＋混合槽＋1U。实际 NAS 为 5QI 9/QFI 9，TUN/N3 双向包关联、路由、捕获丢弃和四时刻独立复算均通过。配置与测量边界详见[本项知识点](../../算法知识点说明/十二步知识点/第一步/3_80B与16B的UDP.md)，命令另页列出。
