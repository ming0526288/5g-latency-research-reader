# 100 到 200 MHz 单 UE 时延现有的解决方案

同一载频的单 UE 回切实验中，两档基站都每隔 5 槽准备一次上行授权。5 槽对应 0.625 ms 的仿真时间，但实际经过的主机时间从 0.222 增至 0.453 ms。这是本机 RFsim 中观测到的运行差异。[带宽回切结果](100到200MHz单UE时延变化的原因.md)

## 已有做法与适用条件

|遇到的问题|已有方法|对本项目的用法|
|---|---|---|
|RFsim 采样处理和搬运较重|OAI 给出两端 `-E` 四分之三采样这个选项，也可检查基带线程的资源占用和处理抖动。|本机 200 MHz、120 kHz、132 PRB 已完成回切验证。`-E` 令 RF 接口报告 184.32 MS/s，但 PHY 选择 3,072 点 FFT，PRACH 遇到 368.64 MS/s 后退出。[方案一实测](100到200MHz单UE降低时延方案一_本机RFsim.md) · [OAI RFsim 官方文档](https://github.com/OPENAIRINTERFACE/openairinterface5g/blob/develop/radio/rfsimulator/README.md#how-to-improve-performance)|
|周期控制数据到来后还要等上行授权|配置授权（Configured Grant，CG）提前给 UE 配好可用的上行机会，终端在满足授权条件时便可使用，省去对应包的临时请求与授权等待。业务相位匹配时更有效，空闲时仍要考虑资源占用。|独立研究副本已跑通 200 MHz 单 UE Type 1。该轮 ping 的平均 RTT 高于前后两轮门限 0。门限 0 使用基站主动发出的动态授权。依据为 TS 38.331 V19.4.0 §6.3.2、TS 38.321 V19.4.0 §5.8.2、TS 38.214 V19.5.0 §6.1.2.3。[方案二：CG 与门限 0 的区别](100到200MHz单UE降低时延方案二_配置授权CG.md) · [3GPP 配置规范版本](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3197)|
|上行或下行的发送机会隔得太久|按业务方向配置 TDD，并看一次闭环内上行和下行机会怎样衔接。|同一配比下还要看可用机会间距、终端处理时序和接入是否通过。条款为 TS 38.213 V19.5.0 §11.1 与 TS 38.214 V19.5.0 §5.1.2.1、§6.1.2.1。已有商用设备试验按包长、负载和 TDD 图样做对照。[工业 TDD 实测论文](https://arxiv.org/abs/2504.00912)|
|有规律的突发包需要少等，长期保留授权又浪费资源|AUGUSTE 学习来包时刻，在预计有包时提前动态授权。|适合作为授权时机和空授权开销的论文对照。作者试验的时延数值属于其平台。[AUGUSTE v1](https://arxiv.org/abs/2606.03664v1)|

工业验收可按 TS 22.104 V19.2.0 §5.2、附录 A.2.2.1 界定工业控制业务的传输间隔、时延与可靠性要求，再按应用的负载和测量边界做测试。5G-ACIA 白皮书 §3 给出测试条件和测量指标，5G-SMART 的实测论文在工厂现场分别统计上行与下行。报告 RFsim 结果时同时保留主机 RTT、无线槽差和仿真推进速率。全程 RTT 包含不同来源的处理时间，不用单一推进比把它换算成真实射频时延。[3GPP 工业控制需求](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3528) · [5G-ACIA 工业测试白皮书](https://5g-acia.org/wp-content/uploads/2021/04/5G-ACIA_PerformanceTestingOf5GSystemsForIndustrialAutomation-1.pdf) · [5G-SMART 工业实测](https://www.mdpi.com/2079-9292/11/3/412)

论文中，P01 用逐包探针量出各层等待与处理，P30 LatencyScope 把调度机会、TDD 和硬件／软件处理纳入单向时延模型。两者可以用来设计计时点、解释差异。实际选哪种优化取决于慢包主要在授权前等待，还是在主机上等样本处理。[P01 原文](https://networking.ifip.org/2025/images/Net25_papers/1571143492.pdf) · [P30 LatencyScope v3](https://arxiv.org/abs/2511.21277v3)

## 本机的四分之三采样已经验证

默认采样在前后两轮均接入并完成 200/200 个 ping。启用 `-E` 的一轮在基站随机接入程序退出，业务没有开始。200 MHz 的现有实验继续使用默认采样。[方案一的完整结果](100到200MHz单UE降低时延方案一_本机RFsim.md)
