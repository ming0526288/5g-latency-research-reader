# 100 到 200 MHz 单 UE 时延变化的原因

我在同一套基站和 UE 程序上，把带宽从 100 MHz 切到 200 MHz，再切回 100 MHz。**ping 往返时延中位数从 0.798 ms 升到 1.380 ms，切回后恢复到 0.805 ms。** 两档的上行授权仍每隔 5 个时隙准备一次，但在主机上，等过这 5 个时隙所用的时间约翻倍。结合两端读样本的计时，主要变化出现在 RFsim 的采样处理和推进速度。

## 同一套程序切换三轮

三轮都只接入一台 UE。固定 n261、载频 27.61236 GHz、SSB 频点、120 kHz、0.625 ms TDD、MCS 上限 9、门限 0、空闲探测后置策略和同一核心网。为在同一载频上放下 66 或 132 个资源块，两档分别使用对应的 Point A、初始带宽部分和 UE 的相对 SSB 位置。

每轮发送 200 个 56 B ping 请求，前 20 个作预热，剩余 180 个计入时延统计。TUN 和 N3 抓包均匹配齐全。

|顺序|带宽|回复／发出|ping 平均 RTT|ping 中位数|ping P99|实发平均间隔|
|---|---:|---:|---:|---:|---:|---:|
|第一轮|100 MHz|200/200|0.813 ms|0.798 ms|1.174 ms|25.050 ms|
|第二轮|200 MHz|200/200|1.385 ms|1.380 ms|1.949 ms|20.441 ms|
|切回验证|100 MHz|200/200|1.054 ms|0.805 ms|5.419 ms|24.549 ms|

切回后，中位数与第一轮只差 0.007 ms。均值仍偏高，主要是第 108、111 个请求的 RTT 分别达到 21.1 和 21.9 ms，抓包显示这两包都慢在上行。这两包保留在统计中，具体卡在上行哪一层还没有逐包记录。三轮的目标发包间隔都是 20 ms，实际间隔如表所示，未做到逐包一致。这里的 P99 用于描述短测样本。

分段抓包显示，第一轮切到 200 MHz 后，上行均值从 0.430 升到 0.766 ms，下行从 0.315 升到 0.545 ms，核心网侧往返只从 0.054 升到 0.055 ms。上、下行分别按 UE 虚拟网卡和基站侧 N3 接口之间的请求与回复计时。

## 为什么都是 5 个时隙，主机上却等得更久

我另开了两轮诊断，仍各发 200 个 56 B ping，开启同一套程序已有的只读计时。两轮平均 RTT 分别为 0.799 和 1.387 ms，变化方向与主对照一致。诊断窗口内的上行授权准备记录，100 MHz 有 20,164 次，200 MHz 有 8,075 次。

|诊断指标|100 MHz|200 MHz|
|---|---:|---:|
|RFsim 采样率|122.88 MS/s|245.76 MS/s|
|相邻两次上行授权准备相隔的时隙数|5|5|
|授权准备到目标上行时隙的距离|4 个时隙|4 个时隙|
|相邻两次上行授权准备的平均主机时间|0.222 ms|0.453 ms|
|基站每过 1 ms 主机时间推进的仿真时间|2.904 ms|1.363 ms|
|基站每次读样本的就绪等待均值|25.92 μs|47.24 μs|
|基站每次读样本的就绪后处理耗时均值|4.52 μs|15.18 μs|

120 kHz 下一个无线时隙是 0.125 ms，5 个时隙等于 0.625 ms 的仿真时间。用这 0.625 ms 除以两档各自的推进速率，得到主机上约 0.215 和 0.458 ms，与直接记录的授权准备间隔 0.222 和 0.453 ms 接近。

**可以确认的是，200 MHz 在这台主机上推进同样数量的仿真时隙更慢，所以相同的授权节奏在实际测量时钟上变长了。** 两档的仿真时钟都比主机实时时钟走得快。200 MHz 每时隙需要处理的样本更多，读样本时的就绪等待和就绪后的处理都变长。空口帧结构、发包计时和主机执行因素各自对单包 RTT 贡献多少，仍缺逐包匹配的 UE 收授权与实际发送时间戳。真实射频的时隙按硬件时钟推进，需要单独实测才能判断其时延变化。

标准依据为 TS 38.104 V20.1.0 §5.3.2 表 5.3.2-2、§5.4.2、§5.4.3.3 表 5.4.3.3-2，TS 38.101-2 V20.1.0 §5.3.5 表 5.3.5-1，TS 38.211 V19.5.0 §4.3.2 表 4.3.2-1，TS 38.331 V19.4.0 §6.3.2 与 TS 38.214 V19.5.0 §6.1.2.1。授权间隔和主机推进速率来自本项目实测。采样计时是 RFsim 实现观测，N3 的路径定义见 TS 38.300 V19.4.0 §4.3.1.1。详细命令和诊断口径见 CHG-480、TEST-635。
