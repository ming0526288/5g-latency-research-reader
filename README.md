# 5G 通信时延研究阅读站

把现有研究说明、知识点、算法、报告、论文和3GPP协议放在同一个可携带的阅读目录中。

## 在另一台电脑使用

```bash
git clone https://github.com/ming0526288/5g-latency-research-reader.git
cd 5g-latency-research-reader
```

下文所有命令都在仓库根目录（能看到`常驻阅读站.py`的文件夹）执行，脚本使用相对路径；移动或重新克隆仓库后，先进入新的仓库目录即可。

进入文件夹，双击 **`打开阅读站.html`** 或 `index.html`。Windows建议使用Edge或Chrome，macOS/Linux也可使用支持MathML和本地PDF的现代浏览器。

## 3GPP 协议的 PDF 阅读界面

当前服务器的 34 个协议分册已从用户提供的 Word 转成 PDF。进入“3GPP 协议”，点击协议即可在与文献相同的 PDF 阅读界面查看、放大和翻页；原 Word、ZIP、分册选择与条款网页检索保留。基础知识中的图 4.2.3-2 引用直接打开 TS 23.501 转换 PDF 第 49 页。

PDF 是本地阅读转换件，非 3GPP 官方下载 PDF；转换页序可能与原 Word 印刷页码不同，精确核对仍保留原 Word。协议原文目录不放转换件。PDF 位于 `阅读转换件/3GPP/`，当前版本清单为 `校验/协议PDF转换清单.json`。

PDF 全文及其本机运行索引 `网页/protocol-pdfs.js` 不上传 Git。新电脑仅克隆仓库不会取得这些 PDF；可通过现有服务器阅读，或在具备 LibreOffice Writer/Math、Poppler 和相同本地协议原文的环境中重新生成：

```bash
python3 -B tools/build_protocol_pdfs.py --jobs 2
```

命令先核对本地原文 CRC/XML/SHA，再转换并生成 PDF 索引与条款页序；不下载协议、不修改原文。未生成预览或版本不一致时，界面明确提示并保留原 Word 与检索页入口。来源、实际命令、抽核范围与失败见研究仓库 CHG-368/TEST-515；未声称 11,827 页均经人工逐页校样。

在当前Linux服务器的VS Code终端，常驻运行并请求打开浏览器只需一条命令：

```bash
python3 常驻阅读站.py
```

该命令安装/启动当前用户的`5g-latency-reader.service`，已有服务则直接使用，不需保持终端运行。新电脑默认仅监听`127.0.0.1:8765`，服务进程退出后自动恢复；再次运行会保留已保存的监听设置。移动仓库后，在新位置重新运行此命令以更新服务路径。当前服务器已启用用户linger与服务开机启动，因此关闭终端、退出登录后也会继续运行；其他Linux电脑如需同样常驻，首次安装后可按脚本提示执行`loginctl enable-linger 用户名`。

只启动或更新常驻服务，不请求打开浏览器：

```bash
python3 常驻阅读站.py --no-open
```

`--no-open`只关闭自动打开浏览器的动作，服务仍在后台运行；命令结束后可以关闭终端。

当前服务器另外配置了受独立口令保护的内网监听：

```text
http://10.29.156.152:8765/index.html
```

连接能访问此服务器的aTrust后，可在浏览器直接输入该地址，不需要VS Code。用户已验证aTrust可达TCP22；TCP8765是否获准通过、手机账号是否拥有相同资源权限，仍需客户端验证。Windows PowerShell测试：

```powershell
Test-NetConnection 10.29.156.152 -Port 8765
```

首次访问内网地址需要阅读站独立账号口令；在服务器终端查看：

```bash
python3 常驻阅读站.py credentials
```

这是阅读站专用口令，不是aTrust或服务器登录密码。口令、哈希及本机设置只保存在`~/.config/5g-latency-reader/`，权限0600，不随Git提交。未登录返回401；隐藏路径和目录列表不提供下载。只绑定127.0.0.1和已明确指定的内网IP，不绑定所有网卡，不改变单位aTrust或全局防火墙规则。

固定密码、增加或删除账号的方法见[修改密码与添加多个用户](#修改密码与添加多个用户)。

本机设置会保存，重复运行常驻命令不会撤掉VPN监听。其他电脑初次克隆仍默认仅本机；如需配置自己的受保护内网地址，可执行`python3 常驻阅读站.py --vpn-address 本机内网IP`。恢复仅本机：`python3 常驻阅读站.py --local-only`。

如果仍使用旧的localhost/127.0.0.1转发网址，则VS Code远程连接仍需保持；上面的内网直连网址不依赖这条隧道。服务器休眠、网络中断、IP变化或VPN未授权时不能保证可达。

查看和停止服务：

```bash
python3 常驻阅读站.py status
python3 常驻阅读站.py stop
```

以下仅是可选的临时模式，当前常驻服务不需要保持终端：

```bash
python3 启动阅读站.py
```

脚本启动仅监听`127.0.0.1`的静态阅读服务，并通过VS Code Remote的`code --openExternal`请求在本地电脑浏览器打开；普通桌面环境则请求本机浏览器。首选端口8765，占用时自动选择后续端口；相同阅读站已经运行时直接复用。若没有自动打开，可在VS Code“端口”面板转发打印出的端口并打开。新启动服务的终端需保持运行，按`Ctrl+C`停止。

在克隆后的其他位置，进入仓库再运行`python3 启动阅读站.py`即可。Windows也可双击`启动阅读站.bat`，直接打开离线HTML，不需要Python。

私有仓库需要使用有权限的GitHub账号克隆。阅读时无需联网、Python、Node.js、数据库或`npm install`。请完整复制/克隆文件夹，不能单独复制入口HTML。

## 修改密码与添加多个用户

账号文件是当前Linux用户目录下的 **`~/.config/5g-latency-reader/login.json`**。首次启用受保护内网监听后自动创建；它在仓库外，移动仓库不会改变此文件的位置。在编辑器中打开它即可修改，无需改Python代码。

旧的单账号格式仍然支持。要添加多个账号，将内容改为下面的`users`数组，保留自己的原账号和密码，再增加新项。以下密码只是占位示例，请替换成自己设置的密码：

```json
{
  "users": [
    {
      "username": "reader",
      "password": "替换成第一个账号的密码"
    },
    {
      "username": "reader2",
      "password": "替换成第二个账号的密码"
    }
  ]
}
```

- `username`是登录用户名，`password`是该用户的固定密码；每个账号都可以阅读同一份资料，没有分级权限。
- 添加第三个用户，就在`users`数组中再加一个对象，相邻对象用逗号隔开，最后一个对象后不加逗号。
- 用户名不能重复、不能包含冒号；用户名和密码都不能为空。JSON使用英文双引号，不支持注释。
- 修改密码直接改对应的`password`；删除用户直接删掉对应对象，至少保留一个用户。

**保存JSON后，在仓库根目录执行下面这一条命令使配置生效：**

```bash
python3 常驻阅读站.py --no-open
```

此命令读取`login.json`，更新供服务校验的`access.json`密码哈希；账号或密码变化时会重启已运行的服务，使新增、修改和删除生效。它保留已有端口和内网监听设置，不打开浏览器，也不会每次生成新密码。单独保存JSON不会立即更新正在运行的服务，保存后要执行此命令。

`access.json`由脚本维护，不需要手动修改。需要查看已配置账号时运行`python3 常驻阅读站.py credentials`。浏览器记住旧账号时，可以使用隐私窗口重新登录。账号文件不随Git同步，在其他电脑上运行服务时需在那台电脑单独配置。

## 阅读功能

- 六步阅读路线；知识点、算法、研究报告、CHG和TEST分类目录。
- 左侧“论文规划与研究路线”放在“知识点”之前，通过“时延优化与算法对照”进入论文规划，查看工业场景、候选方法、强对照、数学分析与实验顺序。
- 左侧知识点分为通信与时延基础、不同TDD、不同SCS、多UE、分层时延、尾时延、算法知识点七类，使用小图标导航；各算法解释统一在“算法知识点”中查看。
- “算法知识点”和“算法实现与结果”先选择算法方向，再进入对应页面。已做方向为 QUEST（含无 HOL 消融）、每 UE SR 周期分配、授权时机、剩余资源预算探测；实现结果可直接跳同一算法的知识页，知识正文也可返回结果。QUEST 的实验对照与阅读候选分别分组，不将候选标为已实现方向。
- “研究结果与分析”列出 TDD、SCS、多 UE、分层时延、尾时延五个已做实验入口，以及“原始源码与当前版本”和算法实现与结果。源码页说明原始代码、累计修复、研究附加功能及各批数据的适用范围，不是第六类时延实验；每类实验仍保留结果图、条件/批次、失败或错误解释和知识链接。
- “研究资料”仅放“文献与材料”和“3GPP 协议”，与实验结果分组展示。
- 本地全文搜索：点击搜索框，或按`Ctrl K`/`/`。
- 行内/独立公式排版，分数、上下标、求和等使用本地KaTeX字体；协议OMML转换为MathML。
- 网页正文中的中文与英文、数字之间自动留空格，叙述中的数值比较与单位显示为`Priority = 5`、`8 Mbps`。
- 阅读字体：英文/数字优先 Arial，中文使用本机苹方、微软雅黑或 Noto Sans CJK SC 等清晰黑体回退；无需联网加载字体。桌面正文18px、手机15px，导航和卡片说明桌面16px/手机14px，辅助说明桌面约14px/手机12px，表格桌面16px/手机14px（均为通常16px根字号下的显示值）；代码/公式保持专用字体，并支持文字大小偏好。
- 原文图片及测量区间示意图。
- PDF 阅读器默认显示比例为 95%，可在内嵌阅读器工具栏自行调整；这只控制显示，不改 PDF 文件字体、分页或网页其他字号。
- 文档相互跳转、右侧标题目录、上一课/下一课。
- 文献PDF页序定位；支持手动选页和独立打开PDF。
- 协议条款、分册、IE关键词定位；支持打开原始Word文件。
- 浏览器本地书签、阅读进度、深浅主题；它们不随Git同步。

## 原文与定位边界

论文与教材使用**本地PDF从1开始的页序**，它可能与印刷页码不同。明确识别出文献和有效页码的引用才建立页码链接；不能可靠识别的引用保留原文，不猜页码。PDF内更精确的段落或公式位置需要在目标页查看。

协议网页是**本地转换阅读页**，不是官方发布网页或官方PDF。保留条款与分册目录；精确排版、合并单元格、原始矢量图及复杂公式应以随仓库保存的Word原文为准。Word里的部分WMF/EMF原图不能直接在浏览器显示，页面会提示打开Word核对。当前库是用户提供版本，未据此声称独立核实了官网最高版本。

历史报告和计划保持各自版本身份。“当前”“下一步”可能是文件写作当时的状态；研究最新接续请从首页最后一步进入。文档网页化没有重新执行实验或重新认证旧结论。代码、原始业务日志、pcap、凭据及实验运行环境不作为阅读附件收录；相应链接会显示来源位置说明。

若PDF未内嵌显示，点击“独立打开PDF”。本地文件模式下书签等功能受浏览器本地存储策略影响，不能视为跨电脑云同步。

## 维护与核验

后续新写或日常更新的讲解说明统一在本仓库`说明/`维护，并在每次交付时更新网页版页面、导航和搜索；用户刷新网页即可阅读。原研究目录的旧说明保留作历史参考，不再同步维护两份正文。静态网页不会因保存Markdown而自动更新，维护者须同时完成页面生成与索引核对；具体约定见`AGENTS.md`。研究代码、原始证据及CHG/TEST仍按原研究规则保存。

实验结果的前置知识包含协议原文定位、字段表、完整公式、可放大的教学图和原结果链接。先核对本地资料，再编辑`说明/`下的源稿；新增页面登记到`说明/knowledge.json`。只更新这些知识页时，在仓库根目录运行：

```bash
python3 tools/draw_prerequisites.py
python3 tools/update_knowledge.py
python3 tools/check_prerequisites.py
python3 tools/validate_reader.py
```

第一条重绘本次教学示意图，第二条更新页面、导航与全文搜索；不重导出原研究工作区。维护需要Python的`markdown-it-py`和Node.js，公式引擎随仓库保存；普通读者继续直接打开网页即可。协议原表的摘录/重排与实验取值、工程假设分开标注，图不冒充新的测量结果。

五类实验说明的唯一正文在 `说明/五类时延分析/`，登记在 `说明/experiments.json`。该目录自带原图、已完成实验的安全汇总副本及来源 SHA；复制或 Git clone 后阅读不需要原机器的实验目录。修改这些页面后运行：

```bash
python3 tools/update_experiments.py
python3 tools/check_experiments.py
python3 tools/validate_reader.py
```

需要重新排版现有结果图时，在装有 Matplotlib 的 Python 环境执行 `python3 tools/draw_experiment_results.py`，再运行上述命令。脚本只读取随站保存的汇总，不启动 RAN、不重新计算原始包时延，也不将旧图改标签冒充新实验。普通阅读不需要绘图库。全量历史导出末尾会重新生成知识页和五类实验页。

算法选择页由 `说明/algorithms.json` 管理，每个方向分别登记知识、实现/结果以及历史版本的来源。运行以下命令可更新分类入口；不重新导出历史工作区：

```bash
python3 tools/update_algorithm_index.py
python3 tools/validate_reader.py
```

新增算法时，独立建立 `说明/算法知识点说明/新算法_知识点说明.md` 和 `说明/算法文档/ALG-006_新算法.md`（编号按实际下一个未使用编号递增），不追加到 QUEST 正文。将两份稿登记在 `说明/algorithm-notes.json` 的 `documents`，例如：

```json
[
  {"source":"说明/算法知识点说明/新算法_知识点说明.md","algorithm":"new-algorithm","kind":"knowledge"},
  {"source":"说明/算法文档/ALG-006_新算法.md","algorithm":"new-algorithm","kind":"results"}
]
```

再在 `说明/algorithms.json` 的 `families` 增加一项，独立的 `id` 与上面的 `algorithm` 相同，填写名称、编号、简介和两个阅读分组：

```json
{
  "id":"new-algorithm", "name":"新算法", "code":"ALG-006",
  "subtitle":"算法副标题", "description":"本算法的阅读说明", "keywords":["新算法"],
  "knowledge":[{"title":"算法知识","documents":[{"source":"说明/算法知识点说明/新算法_知识点说明.md"}]}],
  "results":[{"title":"实现与结果","documents":[{"source":"说明/算法文档/ALG-006_新算法.md"}]}]
}
```

再次执行 `python3 tools/update_algorithm_index.py` 会先生成新稿的页面/搜索数据，再生成算法分类；无需修改前端代码。条目只代表登记的实际状态，未测部分须在正文写明。已有算法的新知识更新对应源稿；新算法另建稿、另建选择卡片。普通阅读不需要运行维护命令，已有全部资料仍可检索和跳转。

普通阅读不需要运行以下命令。导出器用于原始研究工作区，依赖Python的`markdown-it-py`、Poppler的`pdfinfo`及Node.js/KaTeX；不会修改原研究文档。下面假设阅读站仓库位于原始研究工作区内，因此`--workspace ..`指向上一级工作区；若在其他位置，请改成从当前仓库到原始研究工作区的相对路径。

```bash
python3 tools/build_reader.py --workspace ..
```
