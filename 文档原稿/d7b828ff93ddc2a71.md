# 混合QoS多UE的PF／QUEST重复与反序对照：方法和命令

本轮由用户明确要求“让不同QoS的多个UE同时竞争资源，再做PF／QUEST的重复、反序对照”。新代码和新输出都独立于已冻结的quest-reproduction、trial-08及原始RAN/核心部署；Git提交/推送仍取消。实际结果以本目录evidence及CHG260起的记录为准，本方法文件不把预声明条件冒称成功。完成本轮后按用户后续要求整理工作区顶层“研究说明文档总导引.md”。

## 设计：一次只变调度策略

- 每次3UE：1个Non-GBR 5QI69、2个Non-GBR 5QI9；同一小区同时发送UL。UE仅请求已有受支持DNN，SMF按DNN+S-NSSAI本地profile赋予5QI。internet为9、ctnet为69，固定每会话单默认QoS流/QFI9。69不是由UE/应用请求。
- 3个业务种子20301027、20302027、20303027，依次将UE0、UE1、UE2设为69。每个种子做正向和反向接入；每个接入条件各PF和QUEST，算法运行先后顺序平衡。合计6个配对条件/12运行，不称6个独立种子。
- 同一配对内种子、各UE QoS、接入顺序、核心镜像/程序、RAN二进制/模块、无线/CPU/负载/探针/观测相同，仅OAI_QUEST_SCHEDULER为pf或quest。两者均开启同样的16bit/10µs私有HOL-BSR，排除上报开销差异。
- 固定总4Mbps，每UE4/3Mbps，指数到达、1200B、4500包/UE，去500热身后4000统计；12次共162000完整/144000统计。业务110秒/接收120秒，总根预算6000秒，失败即停并保留，不延长期限强迫通过。
- 沿用120kHz/n261/66PRB，周期0.625ms D3/S/U1，S6D/4F/4U，MCS上限9；RU6、UE主线程4/4/4，common mask 0,1,7,12-23。该具体配比/CPU/负载是已验证工程工作点，不是3GPP逐项列出的强制方案。

主指标是69 UE的APP及TUN→N3 P99，同时报告9组代价、全部UE最差P99、均值、交付率和同40慢包等待分解。不把某个UE改善说成所有UE改善，不把APP直接套标准PDB作合规认证。每个配对独立计算`100×(L_PF−L_QUEST)/L_PF`，正值改善，负值恶化；不将不同种子/不同业务包混成单一P99。

## DNN与IP池的实现依据

SMF现有smf_config.cpp解析DNN_LIST及SESSION_MANAGEMENT_SUBSCRIPTION_LIST；smf_app.cpp/get_session_management_subscription_data按DNN和S-NSSAI选择本地配置。smf_paa_dynamic.hpp按DNN维护独立pool，旧配置多个DNN池范围重叠，混合使用可能重复地址，因此只在新副本将活跃internet范围设192.169.0.3–120、ctnet设192.169.0.128–240。同处原UPF 192.169.0.0/16及UE可路由的/24内；接入后仍逐UE拒绝重复IP并核真实TUN路由。不是要求运营商按这些地址配置。

SMF初始N2编码nonDynamic5QI及ARP，没有编码可选QoSPriorityLevel；gNB按标准表取9→90/300ms、69→5/60ms。旧配置的QOS_PROFILE_PRIORITY_LEVEL=1在初建流程未用作该调度P，本轮不改此未使用字段、也不把它混成ARP。未审定/覆盖全部资源修改路径，不能称全面QoS策略认证。

## 必须通过的真实核验

1. 原核心只做一致性只读快照；每个条件用同一快照全新建私有MySQL/AMF/SMF/UPF，不把其他用户实验期间的SQN变化带入配对。检查原容器ID/镜像/启动时间前后相同。只回收latency-mix-*自有资源，数据库匿名卷用自有容器rm -v回收，不prune。
2. 捕获NAS按HTTP请求私有订阅号关联到逻辑UE，输出不带订阅号；逐UE检查QoS规则QFI9及显式5QI。原UE跳过5QI描述内容，故不认证UE完整策略。
3. 按每个UE专有MAC trace确定业务RNTI，再与gNB DRB日志和候选参数核对；N4初建及每个编号N3包QFI9，路由经oaitun_ue1，三类捕获kernel drop为0。
4. 复用原四点/分层/RLC/完整UL服务图核验，13500完整/12000统计/条件；MONOTONIC同包接收减发送为APP时延，外部分段wall口径不与APP混加，P99不相加。
5. 每条候选独立重算PF／QUEST式、核排序单调、HOL来源和缓存；观察同调度轮次不同QoS正估计积压候选，并至少出现配额/RB/CCE未服务，证明实际共同候选竞争。估计缓存不是瞬时真实RLC队列。
