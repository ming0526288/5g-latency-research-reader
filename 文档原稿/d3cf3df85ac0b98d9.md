# 五个时延优化研究方向：通信侧版本

## 研究范围

机械臂、组装车和摄像头用于说明工业应用需求；不修改视频采集、编码、识别、视觉模型和现有摄像头控制接口。研究对象是 OAI 通信侧的等待、排队、授权、传输、HARQ、协议处理以及资源分配。场景设想可以定义“状态上报、控制小包和较大突发流”，但合成流量须标为合成，不将故事当作真实工业测量或控制效果证据。

已有 a/b→UL MCS 上限 14/25 可保留为外部条件，记录实际 MCS；不要把上限当作固定发送 MCS，也不要把 a/b 自动等同于 LOS/NLOS。可用受控序列回放进行通信实验，最终验证仍使用现有接口，无需改变摄像头内容。

用户要求的分层时延、不同 TDD 比例、30/60/120/240 kHz、多 UE、尾时延分析全部作为公共分析与评价轴。下面五项是算法研究方向，不是五个必须各自发表的分析模块。每个方向先固定其他变量得到因果结果，再在完整公共矩阵中验证泛化。

文献编号对应 pdf-英文原版 文件名前缀；空白是针对所给文献的交叉判断，不是全球首创认证。

## 方向一：期限约束的 TDD 配比与周期优化

研究问题：既定业务到达下，怎样选择合法 DL/UL 比例与周期，减少方向等待、队列和重传等待，同时满足上下行期限？主要优化方向资源与等待结构。

算法：队列服务模型＋合法配置搜索。先穷举，再用约束贝叶斯优化选 D/U 和周期，最小化加权平均时延及 CVaR，约束上下行违约率、最低吞吐与处理裕量。首轮在独立实验间切换配置；在线切换必须另实现一致信令和评估中断。

数据：UL/DL 到达时间、包长、期限、队列、SR/BSR/DCI、K1/K2、HARQ、实际方向符号和资源。120 kHz 下从 DDDSU/DDSUU/DSUUU 候选开始，完成接入与反馈验证后再扩展比例和周期。

空白：[16][17][19][20] 已研究 TDD，且 [20] 已优化尾时延图样。可研究实际 120 kHz OAI 的授权与处理约束如何改变最优比例，以及能否通过分层校准模型减少违约。单纯比较 3:1 和 2:2 不足以构成算法贡献。

代码：n261 配置、NR_MAC_gNB/config.c、gNB_scheduler_ulsch.c、gNB_scheduler_dlsch.c 的时域配置/调度。

## 方向二：不同 SCS 下的时延感知授权资源优化

研究问题：在不同 SCS 下，每次分配多少 PRB/数据符号、何时发授权，才能减少分段、队列等待与空资源，避免更短时隙带来更多信令？主要优化传输粒度。

算法：使用实际 TBS、到达预测和处理预算，优化授权大小及支持的时域参数；依据期望完成时间和超期风险分配资源。SCS 初期为实验条件，分别优化；再用合法配置查表选择 SCS。避免将在线切换 SCS 作为第一阶段依赖。

数据：30/60/120/240 kHz 时隙模型、包长/到达间隔、SR 次数、RLC 分段、PRB/符号/TBS、K2、处理时间与重传。固定带宽和固定 PRB 两组；固定 TDD 周期毫秒数和固定时隙数两组。

空白：[2][3] 已发现高 SCS 不一定更低时延，[4] RETALIN 已通过队列调度减少 SR。可研究 OAI 中每次授权大小、整包完成时间、真实 CPU 处理与尾时延的关系，在不同 SCS 下构建处理约束感知的授权策略，而非再次证明短时隙不总是更快。

代码：MAC PRB/TBS 计算、TDA/K2、必要的 UE 队列/分段测量和合法 SCS 配置。

边界：n261 数据通道以 60/120 kHz 为标准候选，30 kHz 使用合法 FR1 配置；240 kHz 完成抽象模型/离散事件分析并明确标注，不能依据 μ=4 枚举宣称当前 PUSCH/PDSCH 链路已可运行。固定 66 PRB 时带宽随 SCS 变化，必须报告。

## 方向三：既定 MCS 状态下的 HARQ 风险感知资源分配

研究问题：保持现有摄像头与 MCS 控制不变，在不同实际 MCS/误码状态下，怎样分配新传和重传资源，减少 HARQ 造成的尾部，同时避免低 MCS 下队列持续积累？主要优化重传与排队的竞争。

算法：估计每 UE/业务在剩余期限内完成传输的概率，以剩余期限、历史 CRC/重传、待确认数据和队列为状态，联合分配新传 PRB 与重传优先级。重传的 MCS/TBS 和 HARQ 进程约束保持协议一致，不任意更改已绑定 TB。建立小候选动作集，以边际违约风险下降分配资源，必要时设置期限临近回退。

数据：现有 a/b 状态和上限、实际 MCS、BSR、各次 DCI/PUSCH、CRC、HARQ ID/NDI/RV、重传轮次、TBS、包与 TB/分段映射、最终到达/丢失/超时。先用受控误码与相关坏信道序列，再实机记录实际情况。

空白：[22][23] 已考虑解码、反馈、控制信令和 HARQ 时延。可研究如何把这些模型映射到 120 kHz OAI 的可执行资源动作，在既定 MCS 状态与 TDD 机会限制下联合控制重传风险和队列尾部。贡献是调度决策与实现验证，不是视觉感知或简单降低 MCS。

代码：gNB_scheduler_ulsch.c 的重传调度、HARQ 状态与新传资源分配；补充逐包关联日志。保留 external_ul_mcs_control 的策略和摄像头接口。

## 方向四：期限风险与公平性约束的多 UE 上行调度

研究问题：多 UE 竞争时怎样降低最差 UE 尾时延、满足控制期限，同时保证其他 UE 最低服务？主要优化 UE 间分配。

算法：以期限违约概率、HOL 紧迫度、队列压力和长期服务债务构造优先级，按风险收益/PRB 分配资源；约束最低服务、资源和计算预算。先可解释贪心，后可原始—对偶更新。与当前调度器、去偏置 PF、RR、EDF/M-LWDF 比较。

数据：1/2/4/8 UE，独立身份与信道，逐 UE 队列/HOL/期限/服务量/重传/时延。固定总负载与固定每 UE 负载分别扫描。BSR 不等于 HOL，需实现报告或校准估计；仿真真实 HOL 只用于 oracle 对照。

空白：[24] QUEST 已完成 OAI 工业多 UE/HOL/QoS 调度，[21] 已有多用户 DL/FBL 分析。可聚焦 120 kHz 少 UL 时隙、HOL 估计误差、既定 MCS 异质性下的最差 UE 风险与公平性，并测量实际算法开销。

代码：pf_ul() 的候选 UE、优先级和 PRB 分配，BSR/HOL 信息。现有 cnt==1 特殊授权和全局 MCS 状态需要单独消融，避免将列表顺序影响误认为算法收益。

硬件边界：现有两主机两射频优先验证 1 gNB＋1 UE；多 UE 先 RFsim，不能用单 UE 多流代替多个竞争 UE，也不能把仿真 CPU 饱和当成无线拥塞。

## 方向五：尾风险约束的预测授权与空授权预算优化

研究问题：稀疏、周期抖动与突发业务，如何提前发上行授权以减少 SR/BSR 等待，并控制错误预测造成的资源浪费和多 UE 竞争？主要优化接入等待。

算法：轻量到达周期/相位预测＋自适应授权窗口；按预测置信度、剩余期限、队列和资源紧张程度，选择何时授权、窗口宽度与 PRB 大小。设置每 UE/全小区空授权预算，期限临近时确定性回退。以 CVaR 和总生成包违约率为目标，测量推理时间。

数据：到达/SR/BSR/DCI/实际发送序列，空授权/有效授权，预测误差，资源开销、多 UE 状态、重传、全部包结果。先分层验证尾部确实主要来自授权等待；否则需要报告算法收益边界。

空白：[5] AUGUSTE 已有 OAI 预测授权，[9] 已有尾时延 PPO，[26] 已用 CVaR。AUGUSTE 明确留下多 UE 拥塞、窗口自适应和信道预测问题。这里可研究不同 SCS/TDD 与拥塞条件下，怎样联合调节授权窗口和预算，降低 P99.9 与期限违约并维持资源效率。

代码：nr_UE_is_to_be_scheduled()、pf_ul()、每 UE 预测和预算状态。比较默认 SR、当前自定义调度、always-on 和 AUGUSTE 风格基线。

## 共同计量要求

- UL RAN 的 t12−t1 与应用单向、DL、闭环 RTT 分别报告；RTT 不直接除二作为 UL 时延。
- 同一包完整追踪分段/TB/重传，各探针区间可能包含等待；t7−t6 是跨端混合段，不是纯传播时间。
- 各段分位数不能相加得到总分位数；对实际尾包做条件归因。
- 跨主机时间戳先校准偏移与误差；转换 RDTSC 不等于两台主机已同步。
- 期限违约以全部生成包为分母，成功包分布与丢失/超时分别报告。
- P99.9 初期至少 10^5 包探索，更多样本与独立重复用于置信区间；相关突发按事件/运行分块。
- 输出均值、P95/P99/P99.9、CCDF、CVaR、违约率、有效吞吐、空授权、PRB 与算法执行时间。
- 使用相同流量、状态/信道轨迹、种子和处理设置进行消融，先模型全矩阵，再 RFsim 代表点，最后实机支持点。

## 建议

在现有平台上，方向一易建立可行配置和资源—等待关系；方向三利用已有 MCS 状态而不修改摄像头，具有直接的通信研究对象；方向四和五适合形成多 UE 与尾时延算法贡献；方向二提供 SCS 与传输粒度的系统性结论。每个方向都有独立优化变量，公共分析全部保留。
