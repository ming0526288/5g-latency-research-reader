# TEST-079 SCS配置生成与采样支持边界

在研究分支latency-scs-full-stack执行：

```
/usr/bin/python3 research/latency-analysis/scs-stage2/prepare.py --output research/latency-analysis/results/scs-stage2/configs-01
/usr/bin/python3 research/latency-analysis/scs-stage2/probe_sampling.py --output research/latency-analysis/results/scs-stage2/sampling-01
/usr/bin/python3 research/latency-analysis/scs-stage2/prepare.py --output research/latency-analysis/results/scs-stage2/configs-02
```

首次生成失败：原120k配置把ssb_perRACH_OccasionAndCB_PreamblesPerSSB_PR写在注释中，严格替换器找不到活动字段并抛AssertionError；未启动gNB/UE、无业务/抓包。修正生成器：缺失时插入活动字段，保留原注释；第二次生成两份配置成功。失败目录configs-01保留，不冒称可运行。

采样函数8个隔离子进程：μ1/273PRB、μ3/66PRB成功；μ1/264、μ1/66、μ2/135、μ2/132、μ4/33、μ4/66均SIGABRT（返回−6）。输出和原函数哈希在sampling-01。μ2/μ4命中“Numerology ... not supported for the moment”；μ1其他PRB命中当前switch支持边界。关闭core dump，未启动任何RAN和业务，**不作为业务时延测试**。

Docker无权限首次读取失败；按工具申请权限后`sudo -n docker ps --format '{{.Names}} {{.Status}}'`成功，已有amf/smf/upf运行，不重建核心网。此前pgrep未发现正在运行的nr-softmodem或nr-uesoftmodem。

依据CHG-050；TS38.104表5.3.2-1/-2支持标准带宽，不代表实现支持任意PRB。原始C common/utils/nr/nr_common.c:get_samplerate_and_bw给出具体失败边界。数学推导不适用于本采样软件支持探针，时域推导见后续报告。
