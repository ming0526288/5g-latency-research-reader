本页业务数据属于保留首UE位置例外时的原策略组。CHG095已移除该调度资格/MCS例外，当前新组见[共同上行调度基线](../scheduler-baseline/按3GPP边界建立共同上行调度基线.md)。本页原数值及程序身份保留，不能改标签冒充新规则复测或直接推算优化收益。

2026-10-21，独立接续实验，CHG092/093、TEST151至156。原五阶段基线数据保留为历史同程序组，本报告使用新增只读C探针后的同一新程序，不合池。

本轮把4 UE大上行时延进一步定位到**首次把该包的RLC分段交给MAC之前**。两次ON的最差UE都是UE1：同总时延最慢40包中，该等待分别占总时延98.91%和99.30%。这是等待位置的实测证据，尚不能区分授权/调度、BSR信息、软件线程推进或其他MAC供给因素，不能称为已根治尾时延。

## 数学与测量路径

```mermaid
flowchart LR
 A[应用发包] --> P[SDAP / PDCP] --> R[RLC接纳 a]
 R -->|W=b-a| B[首段序列化后 b]
 B -->|S=c-b| C[全部初传段序列化后 c]
 C -->|R=d-c 混合剩余区间| D[对端完整RLC SDU交付前 d]
 D --> Q[PDCP / SDAP / N3 / UPF应用]
```

对包i各初传段j，按SO与字节长度验证半开区间不重叠地覆盖[0,L_i)，SN一致、首尾标志对应SI。a取旧event7，b/c取该包初传各段序列化时刻的min/max，d取对端旧event8，时间为同宿主CLOCK_MONOTONIC整数ns：

`D_mixed,i = d_i-a_i = (b_i-a_i)+(c_i-b_i)+(d_i-c_i) = W_i+S_i+R_i`。先逐包核a<=b<=c<=d及精确和，再转ms统计。单段包S=0合法，表示只有一个序列化边界，不能说PHY发送0ms。W含实际排队及获得MAC资源/执行推进之前的等待；S是wall-clock分段跨度，不是空口占用时间；R仍含MAC/PHY/HARQ/RFsim/接收重组，未知机制份额不填0。

均值可按同包集相加。慢包组T_i取该UE按应用总时延最大的同40包：`sum_k E[D_k|T_i]=E[L|T_i]`；各段P99不可直接相加。这是4000样本的条件均值，不是可靠P99.9，也不解释原100000样本长OFF的内部机制。

## 分段、重传与尚未确认的机制

统计窗口内N1 b1的初传段数1/2/3/4分别42/221/1915/1822包；b2为15/236/1530/2219包。N4各UE以2段为主，所有直方图在安全summary.json逐流保留。N4段数较少但首次等待更大，不能仅用分段数解释全部大时延；本测点中的请求预算是MAC向RLC索取的上限字节，不是实际TB大小，尚未拿逐TB授予的PRB/TBS或DCI来核因果。

40000个ON统计包的对端交付前RLC重传观测均为0，交付后冗余RLC重传也0。探针的重传路径已在生产核心金样本中实际触发7次，所以不是只声明无重传事件的空检查。但RLC重传不是HARQ，无RLC重传不能推出无HARQ或其时延0。统计前500包及信令事件不混入该结论。

下一步在保持本测量口径下，把UL授权/BSR/逻辑信道出队与实际TB及HARQ代际关联，另测RFsim等待；区分实际资源不足和软件执行推进。未实施NR调度优化算法。60kHz、TDD长周期等旧未完成项仍在START_HERE，不以本项补探针宣布五阶段全部完成。
