# CHG-021：120 kHz gNB＋软件UE＋既有5GC

分支：`latency-tdd-rfsim-sa`，从第一项`latency-tdd-analysis`创建。原目录、原始配置、第一项历史分支和第二项分支均保留。本次不推进第二项。

目的：补充之前仅启动gNB的预检查，实际启动软件UE，核验120 kHz、.625 ms、3:1/2:2/1:3的完整SA接入及小样本业务连通。

新增 `tdd1/sa_rfsim_check.py`：生成隔离gNB配置，N2/N3源地址改为Docker网桥172.11.200.1，AMF地址改为172.11.200.14；保留120 kHz、66 PRB、n261、S=6D+4灵活保护+4U、min_rxtxtime=4。三个候选只改变完整D/U数量。软件UE配置从原始ue.oiwireless.conf复制到忽略目录，不改密钥、不改数据库用户。

启动已有部署的AMF、SMF、UPF，保留已有MySQL/phpMyAdmin，使用`docker compose up -d --no-recreate`，避免原run-5gc.sh中的失败后整体down重启路径。PLMN466/92、TAC100、internet DNN与已有部署匹配。

初版脚本：同机RFsim两端启动，限时保存日志及接口快照，有UE地址才执行五包ping；finally停止本次RAN进程组，禁用core dump。第一轮N2与TCP已连接，但没有同步/注册/UE地址；不能当成接入通过。

第二次修改：增加`--continuous`诊断选项，两端同时加入`--continuous-tx --thread-pool N`。这是RFsim样本连续传输与线程池执行方式的联合改变，不改变TDD调度图样；未逐项隔离，不能断言单独某个开关就是唯一原因。连续发送样本不等于新增可用UL/DL无线调度机会。

第三次修改：配置生成器增加`--down/--up`，限定D+U=4，维持五时隙图样；测试2:2和1:3。

第四次修改：增加显式接入成功判据和退出码：AMF关联、UE同步、RRC连接、RegistrationComplete发送、UE地址、GTP-U隧道、ping、两端存活及无运行中断言全部满足才返回0。前四轮初版脚本退出0只说明脚本执行与清理成功，实际连接结果以日志及status为准；失败首轮保留。最终3:1重跑验证新判据。

新增`archive_sa_check.py`：归档命令、配置、状态、ping和筛选后的阶段日志。新增`validate_sa_check.py`核验归档/源日志哈希、判定、DU配置、命令、进程清理和无鉴权数据。原始完整日志及含鉴权信息的UE配置仅留在忽略results；归档保留原日志SHA256，不提交鉴权密钥。没有改OAI通信源码，使用之前独立编译的二进制。README与原研究报告增加补充结果入口，旧测试历史不重写。

运行命令、五轮结果见TEST-035～039与《第一项_120kHz_gNB_UE_5GC接入核验.md》。这不是受控MCS9/10Mbps时延实验；五包ping只作连通性诊断，不计算尾分位数。
