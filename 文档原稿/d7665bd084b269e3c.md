# 第一轮：多UE上行服务顺序优化试验

2026-10-26，用户明确授权从算法研究路线开始实施。分支 `latency-queue-service-pilot`，父基准 `99dc19cae729e8368ab692b9c35971d1b0fef273`。工作目录沿用独立修正工作树，不触碰原始 oi-wireless-ran；旧 latency-mac-header-fix 分支、旧构建和原始数据保留。

## 目标与边界

问题：在同一TDD/SCS、到达负载和主机安排下，对已有待发数据而久未分配新传授权的UE适当升权，能否降低最差UE的上行P99？先研究服务顺序，资源额度、预测授权、强化学习均留到后续独立步骤。不是QUEST/RETALIN完整复现，也不预先认定排序是慢包主因。

当前六条件依据见 `../service-process/修正后多UE服务过程与慢包分析.md`。它支持积压和服务间隔问题，尚缺候选资格/拒绝原因，不能唯一归因CPU或PF。

## 算法定义与数学边界

gNB可见的待分配字节估计为 B_i=max(estimated_ul_buffer-sched_ul_bytes,0)。这不是精确的UE真实队长。

在每次pf_ul调用的调度轮次k，若已接入且未UL失败的UE有B_i>0，计数a_i加1并饱和；B_i=0则清零。成功安排一个B_i>0的新传授权后清零。重传不作为新的服务计数。计数表示“已观察积压但尚未再次分配新传授权的轮次”，包括因资格不足而跳过的轮次；不是包HOL、物理ms、CPU等待、成功解码时延或硬服务间隔保证。

基础PF权重 p_i=approximate_TBS_i / historical_throughput_i；候选权重

`s_i=p_i*(1+min(a_i,8)/8)`。

等待倍率在[1,2]，8轮是第一版预声明工程参数，非3GPP或论文指定值。仅对原本进入有数据新传候选集的UE升权；SR/不活跃探测授权、HARQ及原资源检查路径均保留。关闭算法时直接返回原p_i，不经过浮点乘法。无期限保证、无最优性/新颖性证明；原PF的正无穷初始权重另按比较器确定处理，不谎称已取得精确HOL。

第一轮同一新二进制切换PF与WAIT模式，具有相同基础排序修正及观测开销。原比较器只返回0/1，先验证其排序契约；基础正确性修正不计算法收益。旧6条件只能作为旧程序历史背景，新PF需实际重测。

拟定目标：降低每条件的 max_i empirical_P99(L_i)，同时报告全部已发包的交付/未完成、有效吞吐、公平性、服务等待、分段及处理开销。4000统计包/UE的P99是描述性结果，不据此认证P99.9/10^-5违约率；不删慢包、不改变业务负载获取虚假收益。

## 首轮完整栈计划

固定120kHz/n261/66PRB/MCS上限9、上述TDD、RU核6、UE主线程共享核4、其他RAN mask 0,1,7,12-23；UE使用已经纠正MAC短子头的程序。5GC+gNB+UE及UDP UL，保留路由、N3和包级图核验，不把ping RTT当单向时延。

每UE4500包、前500热身、1200字节、固定总4Mbps、指数计划到达。顺序预声明：N1 PF/WAIT，N4 WAIT/PF，N8 PF/WAIT（种子20266026），N8 WAIT/PF（种子20267026）。这是可行性试验，N1/N4单块不证明种子稳健。发包/接收期限110/120s沿用4M口径；独立过程上限4200s，来自本次授权，不延用过期24h窗口。

新增小型原因观测必须有固定容量、溢出计数及同臂一致开关。按轮次/UE记录候选或直接跳过原因；容量溢出则结果不可作完整原因分析。全栈首次失败即停止本轮，不自动延时/重试；先保留并分析失败，再另记录必要纠正。

完成顺序：协议/实现核验 → C生产函数测试 → 独立gNB构建 → 计划/输入冻结 → 新完整栈对照 → 独立数值核验/说明/Git。本文是预声明，尚不代表这些步骤通过。实际结果见最新CHG/TEST。
