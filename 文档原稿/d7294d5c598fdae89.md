# 多UE时延研究：如何选基线与不同场景对照

2026-10-29，用户授权联网查找。结论：当前项目保留固定研究版本的OAI/PF为工程主基线；时延强对照采用EDF、M-LWDF，QoS作用分析加入PB；QUEST为被研究算法。不同研究层次要配不同基线，不是从六算法里找一个“3GPP指定算法”，也不是只挑测得最差的算法作为对照。本页是基于下列原始资料提出的实验设计建议，不代表行业统一规则或新增已测收益。

## 1. 官方资料实际说明什么

- OAI官方MAC文档的General说明其PF机制。[OAI官方文档](https://github.com/OPENAIRINTERFACE/openairinterface5g/blob/develop/doc/MAC/mac-usage.md)。本地旧fork的pf_ul与当前develop的函数/流水线不同，联网文档只支持选型背景，不能直接冒称本机运行了网页最新版。
- 官方仿真器将RR、Best-CQI和PF列为可选策略，分别体现等机会、偏好较好信道和折中目标。[MathWorks R2026b文档](https://www.mathworks.com/help/5g/ug/overview-nr-scheduler.html)。这不是强制行业基线；RR等机会不保证等吞吐或等时延，Best-CQI也不能与任何实现中的MT无条件等同。
- srsRAN官方配置有QoS/GBR/PF相关控制；实际UL与DL信息能力要分别查源码。[配置](https://docs.srsran.com/projects/project/en/latest/user_manuals/source/config_ref.html)、[官方QoS源码](https://github.com/srsran/srsRAN_Project/blob/main/lib/scheduler/policy/scheduler_time_qos.cpp)。本次读取的compute_ul_qos_weights向组合函数传delay_weight=1.0；不能仅看到pdb_enabled就声称UL已按真实HOL/PDB加权。该发现限所读main版本，不泛化到所有历史/后续版本。
- QUEST正式本地论文§VI-C/PDF8比较MT/PF/PB/EDF/M-LWDF，故复现不能只留PF而删掉表现更好的EDF等。[作者仓库](https://github.com/tum-lkn/QUEST)说明其TechRxiv v1为相关版本；本地正式期刊原文仍按自身版本引用，不把预印本改标签当正式版。
- AUGUSTE v1保留PF分配，论文基线是未主动预测授权的OAI；它主要改变UE进入调度的时机。[原文](https://arxiv.org/html/2606.03664v1)（本地PDF实际§III-B/C、§IV/V，PDF3–5）。所以它的主要比较维度是请求驱动/主动授权及开销，而不是简单替换PF为QUEST。arXiv记录本次只显示2026-06-02的v1，未认证其他渠道全版本。

## 2. 按场景建议的基线组合

下表是本项目的设计建议；“候选”不代表已经实现。单一算法不能代表所有场景最佳。

|研究场景/要回答的问题|建议基线组合|应重点报告|本项目状态/边界|
|---|---|---|---|
|一般多UE、吞吐与公平折中|固定OAI/PF；RR作等机会参照，MT作吞吐导向参照|逐UE吞吐、公平性、排队/尾时延|PF/MT已做；RR尚未实现/未测，不能写已有数字|
|实时业务/明确时限、多UE慢包|PF工程主基线，加EDF、M-LWDF强时延对照|P99/P99.9样本量、超期/未交付、最差UE及全部UE代价|已有六算法版本；EDF是本实验论文式剩余PDB代理，不是假定gNB知道逐包未来截止时间|
|不同5QI/PDB的混合QoS|PF+PB+EDF/M-LWDF；QUEST为研究算法|高优先级收益、低优先级代价、按QoS拆分及整体最差|真实69/9/9下PF/QUEST已重复；不能用早期全9六算法结果代替新的混合六算法全量比较|
|SR前等待/来包预测/稀疏突发UL|保持同一PF分配，比较请求驱动基线、预测主动授权；始终主动授权作较高开销参考|尾时延与空/小授权、资源/控制开销的联合曲线|AUGUSTE尚未复现；始终调度不是理论最优或零时延下界，必须测实际成本|
|周期性工业上报、资源可预留|请求驱动动态授权作工程基线；CG作有条件补充|周期相位误差、空资源/冲突、可靠性和时延|CG须实际协议/UE能力/平台实现核验后才执行，目前未实施，不能把机制支持当已测效果|
|纯TDD配比/SCS/UE数的时延分析|固定同版本PF及业务/报告链，只改变预声明分析变量|分层/尾时延与资源容量，报告失败/过载|不能同时改调度算法再把差异全归TDD/SCS；SCS比较预先说明带宽/PRB口径，合法配置逐项核|
|接近容量/高负载/服务不足|PF与时延/公平对照按相同输入比较|未交付/丢弃、队列增长、最长未服务间隔与各QoS代价|只统计收到的包会漏掉更严重的等待；不能承诺超负载下任意算法都低时延|

M-LWDF的经典理论结果有特定信道/到达模型和可稳定负载范围，不是“任何NR实现P99都最小”的证明。[原始研究摘要](https://www.nokia.com/bell-labs/publications-and-media/publications/scheduling-in-a-queuing-system-with-asynchronously-varying-service-rates/)。所以上表叫强对照，不预先指定赢家。

## 3. 当前项目具体保留什么

建议区分三层，全部是后续实验的选择说明，不在本页启动测试：

1. 工程参考：固定已核验研究版本PF，记录真实C/ELF/配置身份；需要总方案部署成本时，另做不带私有HOL的PF参考。
2. 同开销公平比较：PF、PB、EDF、M-LWDF、MT、QUEST采用匹配的HOL上报开销、相同实际信息与主机/无线/业务条件。PF对QUEST不能单独识别HOL贡献。
3. 机制消融：若论文要证明HOL作用，新增保持其余QoS/PDB/TBS项的QUEST-no-HOL等独立对照；它不等于PB。尚未实施，不预写收益。RR/CG也仅候选，不能填当前已有结果。

PF作为主基线回答“相对现有平台改进多少”；EDF/M-LWDF回答“是否优于已有时延策略”；PB帮助观察优先级偏置；MT显示吞吐导向的代价。必须连同实际最强对照和负面条件报告，不能只拿差的MT证明新算法更好。现有同QoS B1中EDF低于QUEST，而混合QoS六配对的69收益伴随其他UE代价，支持保留多种对照。

相同开销不等于可以给新算法未来包到达/真实未报告队列，而基线只能看旧BSR；必须说明每种算法实际可获得的信息。已有的私有HOL实验仍是配对格式，不能称标准DSR或商用UE透明互通。

## 4. 调度层次不要混在一起

QUEST主要研究“已有候选怎样按QoS/HOL排序”；AUGUSTE主要研究“什么时候提前提供上行机会”。本机已有记录还显示候选前no_data/请求链等待，所以只在候选里改排序可能覆盖不到全部慢包。当前18条件SR分配是另一项静态资源实验，不能改称这两篇算法的同一次复现。

AUGUSTE v1实验还明确关闭Confident→Learning回退以隔离预测状态性能；未来若复现，必须把论文该评估口径和完整状态机运行分开，不能只报较理想一段。基线始终保留不主动预测的OAI，PF分配尽量保持同一版本，另报告实际控制成本。此处尚无实现或本机收益。
