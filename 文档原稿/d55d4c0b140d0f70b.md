# TEST-085 同配置接入失败诊断复测

不改gnb.conf/ue.conf/radio.json，不改25秒接入判据；仅CHG-054新增退出码记录。两次旧失败保留。

实际命令：

```
sudo -n /usr/bin/python3 research/latency-analysis/scs-stage2/run_ul.py --configs research/latency-analysis/results/scs-stage2/configs-03/mu3-p2p5-d5u14 --output research/latency-analysis/results/scs-stage2/mu3-d5u14-ul-02 --ratio 5:14
```

业务结果只在完成四边界关联后进入汇总；没完成时不填0，不取接入时长冒充包时延。

实际补执行：

```
sudo -n /usr/bin/python3 research/latency-analysis/scs-stage2/run_dl.py --configs research/latency-analysis/results/scs-stage2/configs-03/mu3-p2p5-d5u14 --output research/latency-analysis/results/scs-stage2/mu3-d5u14-dl-02 --ratio 5:14
/usr/bin/python3 research/latency-analysis/tdd1/analyze_packet_capture.py research/latency-analysis/results/scs-stage2/mu3-d5u14-dl-02
```

UL复测runner退出1：完成PHY同步、无RRC连接/注册完成/TUN，25秒超时；业务和抓包均未开始。回收后的gnb=0/ue=1是**超时后清理的最终返回码**，不能据此说UE在超时前已异常退出。未取得单向业务时延；接入根因未定位，不能说协议不允许5:14。同步SSB33与此前一致只是观察，不证明SSB根因。

DL复测runner/analyzer退出0：同配置完成完整业务，4500发送/接收/N3/TUN关联、4000统计，零丢包重复。MONOTONIC均值0.692642805ms、P99=1.28395541ms、最大4.853601ms。流量结束时gNB/UE存活，回收后UE=1属清理后的值，不判流量失败。原DL初次已完成随机接入和RRCSetup接收，在Applying CellGroupConfig日志后提前退出；初次未记录提前退出信号，根因仍未知。一次复测通过不代表接入可靠，也不代表UL通过。

全轮14次尝试：11次完整四边界、49500匹配包/44000统计，3次未进入业务（原UL、原DL、UL复测）。没有覆盖旧失败、延长超时或更改任何无线字段。
